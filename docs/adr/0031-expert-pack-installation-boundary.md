# Expert packs retain snapshots while members remain independent

Status: accepted

SkillHub's observed expert-pack protocol provides a workflow and membership without an addressable pack release version; its CLI lock cannot preserve the complete member coordinates and confirmed versions required by ADR-0030. Skills Box retains a scope-specific Pack snapshot containing the confirmed workflow, member identities and individual Marketplace versions. The pack remains a visible association of independent Skills: multiple packs in one Scope may share a member, while each Scope owns its installations independently. The snapshot preserves what the user installed without treating later member updates as a new pack release or silently following later upstream membership changes.

Pack installation downloads and verifies the required content before publishing members. Publication retains successful results if a later step fails, extending ADR-0021's partial-result principle; the Pack workflow is installed only after all members and their selected Agent attachments are ready. A failed installation remains visible as incomplete. Member Update, Detach, Remove from Agents and Uninstall remain available; removal previews identify affected packs and their observed completeness is refreshed afterward. Whole-pack Update and Uninstall are outside the initial feature.

An existing member is reusable only when it is a Managed skill with the same complete Marketplace coordinate, intact canonical content and no Local modification. The preview retains its current installed version and may add missing selected attachments; pack installation does not implicitly upgrade, downgrade or adopt occupied content. Missing members are resolved to explicit Marketplace versions. Completeness across selected Agents and deviation from the Pack snapshot are separate observations, so an independently updated member remains present while its changed version is visible.

An incomplete installation offers a newly previewed completion of missing skills and original selected attachments from its Pack snapshot, without reinstalling successful members or silently adopting upstream membership changes. A clean member independently updated since installation retains its current version and is shown as differing from the snapshot; a missing member still requests the original recorded version. Publication cancellation settles the current unit before stopping; an interrupted task does not resume automatically. The workflow can be uninstalled independently, leaving members and an incomplete pack record, and is excluded from upstream Update and Update all in this first release.

Forget expert pack removes the scope-local grouping while preserving skills, attachments and their independent source records. Reinstallation may reuse a retained workflow only when its source identifies the same pack, its previewed content and member-name mapping match, and it has no Local modification; otherwise the user must resolve the occupied entry before installing. Local snapshots remain readable when upstream content changes or becomes unavailable. Original selected Agents remain the completion targets; additional attachments use existing skill management and do not silently change that target set.

This extends ADR-0030's installation identity to the Pack workflow without changing member coordinate/version identity or publication under the original Skill name. Workflow adaptation is defined in [ADR-0032](0032-expert-pack-workflow-adaptation.md); full behavior and acceptance scenarios are in the [design specification](../../.scratch/skillhub-packs/spec.md). These decisions were confirmed in Q1–Q23 on 2026-11-11, and the user confirmed the complete specification in Q24. The design interview is complete; implementation is pending. Protocol evidence is in the [official-contract investigation](../../.scratch/skillhub-packs/research/01-official-contract.md).
