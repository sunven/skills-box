# Global Skills become independent Project copies

Status: accepted

On 2026-11-04 the user chose to make selected Global Skills available in one Project by copying their current content into that Project's Canonical store, then creating any requested Agent attachments there. The Global Skills remain intact, and later Global updates or Uninstall do not change the Project copies. Linking Project attachments directly to the Global store was rejected because Project content should remain independently managed. This records Copy to project's content ownership; it does not redefine Attach as a cross-Scope action.

This extends the [original Project feature boundary](../../.scratch/project-scope/spec.md) to allow cross-Scope copying while retaining separate Project identity, content and management state as established by ADR-0011. The operation has one read-only source Scope and one destination Scope; ADR-0021's existing same-Scope Batch operations retain their scope. Existing same-name Project content is reused only when identical and is never overwritten; different content is skipped, and reuse preserves the Project's management records. Partial success is retained: a successful copy remains if a later Agent attachment fails, and retry only revisits failed or unexecuted targets.

New copies retain the known upstream association and use their actual copied content as the Project starting version and local baseline. Native creation of the Project installation record is a scoped exception to the CLI-owned lock rule: the existing CLI installs from upstream and cannot represent a copy of current local content. Leaving the copy unmanaged was rejected because the user expects independent Project update checks and existing Attach behavior. Global Git tree hashes cannot be reused as Project content hashes; the Project record describes the copied version, which may differ from upstream even when upstream has no new commit. Reusing existing Project content never upgrades an Unmanaged skill or replaces its records.

Selecting a new directory creates only a bounded, read-only preview, without registering a Project, activating it or creating a baseline. This narrowly extends ADR-0011's registered-root read boundary for an explicit pending Project root; ordinary content commands keep their registered-root boundary. Final confirmation validates and registers or reuses the Project while preserving the active Global Scope. A confirmed registration remains after failure or stopping. Internal relative links are retained only when they still resolve inside the independent copied Skill; absolute, external or broken links reject that Skill rather than preserving a hidden dependency on Global content.

The design and its accepted interview answers are recorded in [the feature spec](../../.scratch/batch-attach-scope/spec.md).
