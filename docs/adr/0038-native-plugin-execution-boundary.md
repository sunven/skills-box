# Native plugin operations use official interfaces and observed state

Status: accepted

Skills Box uses the hosting Agent's official CLI for Plugin and Plugin marketplace operations, including Codex's official configuration write interface for Plugin enablement. The reference application's direct TOML editing is not inherited as a fallback: if an operation cannot be performed reliably through the selected official interface, that operation remains unavailable with a specific explanation.

Direct configuration editing could bypass CLI gaps, but would make Skills Box maintain a second interpretation of native configuration precedence and write semantics. Each host adapter provides its implemented actions and market source formats without an exact-version allowlist or minimum-version gate. Availability still depends on configuration ownership, installation scope and readable native state; command responses and post-operation state determine the reported outcome. Unexpected responses or effects disable the affected action for that CLI build. Version and executable identity remain part of failure-cache keys and confirmation fingerprints, not initial permission to operate.

On 2026-11-20 the user explicitly removed the shipped version allowlist after a Claude Code upgrade disabled market operations. This supersedes the earlier policy of withholding actions until that exact build had verification evidence; it does not claim every CLI version is compatible. The optional isolated compatibility check can disable or restore the basic actions it actually tests. It preserves source formats and the existing state of market sync and cascading removal, including observed failures, because the basic fixture does not test those effects. Historical release verification remains evidence for its recorded versions rather than an access list.

Native side effects remain explicit product behavior: market synchronization is separate from rereading state, Codex reinstall is not presented as a guaranteed upgrade, and market removal requires checking its actual impact across installation scopes. The initial user-level release blocked removal when any Project installation was affected or the impact was indeterminate. Those choices were confirmed as Q10–Q14 in the 2026-11-19 [design interview](../../.scratch/native-plugin-management/spec.md), extending [ADR-0037](0037-native-plugin-state-ownership.md) without changing the existing Skill mutation executor.

The Project support decisions in [ADR-0040](0040-native-plugin-project-context.md) extend that scope boundary: writes target the selected Scope and native configuration layer; shared content updates may cross scopes with determined effects and explicit confirmation, while deletion of another layer's installations or declarations remains blocked. Indeterminate effects still block the operation. Official-interface and observed-state requirements are unchanged.
