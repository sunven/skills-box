# Marketplace installations own their version records and execution adapter

Status: accepted

SkillHub installs named releases into namespaced directories and maintains its own lock, while Skills Box identifies local installations by Scope and original skill name. The inspected SkillHub CLI can download an explicitly requested version but report the current latest version in its lock and JSON output; package metadata can also disagree with the marketplace's version label. Skills Box therefore owns scope-specific marketplace Lock entries containing the complete Marketplace coordinate, the confirmed Marketplace version and the installed content baseline. They project into the same managed inventory as Git installations but remain isolated from Git CLI-owned lock records. Pretending a marketplace item is a Git source, or treating CLI lock metadata as authoritative, would lose the confirmed release identity.

Install and Update use the detected SkillHub CLI with an explicit namespaced coordinate and version in an operation-isolated staging directory. The application verifies the staged skill and publishes its original name to the Canonical store, records the request and observed content, and creates Agent attachments through the existing mutation protocol. Update checks read marketplace metadata and compare platform version labels; same-version content replacement is outside this feature. Local content baselines still detect local modification. Neither a CLI exit code nor a local content hash proves the platform's release content is immutable.

Marketplace browsing and Update checks use read-only source access. Local Attach, Detach and Uninstall use native application operations so they remain available without SkillHub CLI; Install and Update require that CLI. This is a source-specific extension of ADR-0001's execution boundary: existing Git mutations retain their executor, while marketplace installation records and local removal are application-owned. It avoids giving a missing marketplace CLI authority to disable unrelated Git or local operations.

The adapter retains ADR-0003's write ownership, backups, cancellation and verification, ADR-0008's result lifecycle, and ADR-0026's command preview and actual invocation contract. CLI staging failure leaves the existing installation intact; failures after publication begins retain required backups and report observed results under the existing recovery rules. The persistence wire format is an implementation choice constrained by source isolation, atomic record publication and compatibility with existing Git operations.

Evidence and confirmed product behavior are recorded in the [marketplace specification](../../.scratch/skill-marketplace/spec.md) and [SkillHub investigation](../../.scratch/skillhub-install/research/01-install-feasibility.md).

Implementation stores v1 marketplace records in `.skills-box-marketplaces.json` beside each scope's Git lock. The public SkillHub command is `skillhub --skip-self-upgrade install slug@version --namespace namespace --dir staging --json`: an explicit `--namespace` avoids the CLI's fallback from a failed namespaced public lookup to saved enterprise configuration. Publication verifies the official download URL and requested coordinate/version in the CLI lock, in addition to the result directory and confirmed SKILL.md. The [implementation and verification record](../../.scratch/skill-marketplace/implementation.md) describes the shipped operation eligibility and isolated real-CLI validation.
