# Project plugin management preserves native configuration layers

Status: accepted

Skills Box shares its Project registry and active Scope between Skill and native Plugin management. A Project's Plugin view includes inherited user Plugins alongside Project installations and configuration, while preserving each setting's native configuration layer: Claude Code offers shared Project and personal Project configuration, with shared configuration as the default. Plugin marketplace declarations belong to those layers; shared native content and installation records remain owned by the hosting Agent rather than becoming separate per-Project Skill stores.

Treating the selected Project as a physically isolated Plugin installation would hide inherited availability, confuse shared marketplace content with a Project declaration, and lose the distinction between configuration committed for collaborators and personal overrides. The UI therefore identifies installation origin, configuration ownership and observable effective state separately, and exposes each host's actual capabilities. This extends ADR-0037's initial user-only product scope without changing its native ownership principle; official-interface and recovery principles in ADR-0038 and ADR-0039 remain in force.

Marketplace synchronization, Plugin updates and reinstalls may change shared content across scopes only when their effects can be determined, the affected objects are identified and the user confirms. This does not authorize changing other configuration layers' enablement or deleting their installations. Uninstall and marketplace removal remain confined to the selected Scope and configuration layer; operations that delete another layer's installation or declaration, or whose effects cannot be established, are blocked and delegated to the hosting Agent's own management tools. Allowing every native cascade would make a Project action unexpectedly destructive elsewhere, while prohibiting all shared content changes would prevent normal native updates; the distinction preserves useful updates with an explicit deletion boundary.

Project support retains the official-interface boundary even when it limits available actions: the isolated Codex 0.170.0 probe rejected Project configuration writes, so the current implementation must explain unavailable Project writes rather than redirecting them to the user configuration or editing files directly. Relocate preserves the app's Project identity and rereads the new root; it does not migrate native Plugin content or rewrite the host's old project-path installation records. Those records remain native facts to reconcile through the hosting Agent.

The user confirmed Q1–Q9 and then accepted the complete specification and acceptance conditions in the 2026-11-20 [Project plugin interview](../../.scratch/native-plugin-project-scope/spec.md). The design is ready for implementation; this ADR does not claim the feature has shipped.
