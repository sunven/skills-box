# SkillHub 专家包安装

状态：已实现并验证；详见 [实施记录](implementation.md)。
日期：2026-11-11。
交付类型：产品实现、设计规格、领域术语、架构决策与验证记录。

## 目标与范围

在现有技能市场增加「专家包」页签，使用户能够浏览、搜索、查看公开普通专家包，并将工作流入口及全部成员安装到一个 Scope、挂载到同一组已选 Agent。安装后保留可查看的包关系和安装快照，同时继续使用现有单技能管理能力。

支持全局与项目 Scope，二者分别安装和管理。首版包含安装、未完成安装的补齐、本地状态展示和忘记专家包；不包含 SOUL.md 角色组合包、整包更新、整包卸载、独立的整包挂载操作、任意替换或跳过成员。

## 领域与安装身份

领域定义以 [GLOSSARY.md](../../GLOSSARY.md) 为准。

- Expert pack：围绕任务组合的 Pack workflow 和 Pack members。
- Pack workflow：作为包入口的独立 Skill。
- Pack member：包引用的独立 Skill；同一 Scope 的多个包可引用同一份安装。
- Pack snapshot：此次安装确认的工作流、成员身份及成员版本，作为后续补齐和差异展示的依据。
- Forget expert pack：移除当前 Scope 的包分组和关联，保留技能、挂载及独立来源记录。

包身份按 Marketplace source 与官方包标识区分，本地安装再由 Scope 区分。成员身份使用完整 Marketplace coordinate，发布到 Canonical store 时仍使用成员 SKILL.md 声明的原始 name。包的市场标识、入口的本地 Skill name 和成员的市场标识不能混用。

工作流来源关联到 Expert pack 与确认内容，不伪造普通市场 Skill 的发布坐标或平台版本。工作流在本地作为受管 Skill，来源记录和内容基线独立于可忘记的包分组；忘记分组不会把它或成员变成非受管技能。

## 浏览、详情和本地入口

- 技能市场的「专家包」页签支持列表、搜索、详情及安装，沿用现有市场分页和请求结果交互。
- 详情展示官方名称、摘要、工作流说明和全部成员；可打开成员详情。
- 详情同时展示当前 Scope 的安装状态、本地入口与成员链接。明确区分市场当前内容与本地安装快照。
- 入口与成员保留在现有技能清单中，标注所属专家包；一个成员可能属于多个包。
- 通过本地技能上的包关系仍可查看本地快照和成员状态。断网或上游下架不会阻止读取本地记录及执行已有的本地管理操作；远端内容按实际可用性显示。
- 无法安装的公开条目仍可查看详情，并显示具体原因。是否具备 CLI 只限制需要它的操作，不阻止浏览或已有本地管理。

## 安装预览与确认内容

一次安装固定一个 Scope 和一组 Agent；入口与全部成员使用同一组目标。前端展示以下内容，用户确认后执行：

1. 包身份、官方工作流、最终将安装的入口内容及适配说明。
2. 每个成员的完整来源、市场标识、本地 Skill name 和具体版本。
3. 每个成员将新增、复用或补挂载，以及已有版本与此次采用版本。
4. 目标 Scope、Agent、冲突、不可安装原因和预期操作。

Pack snapshot 保留官方工作流原文、最终入口内容、成员清单、解析后的身份和本次采用的成员版本。原 Agent 目标集随安装记录保留。已有受管成员采用其当前版本；新增成员采用预览时解析的明确平台版本。

官方包尚无已验证可指定的发布版本，因此应用以确认内容保存 Pack snapshot，不将工作流 frontmatter 的 version 或 manifestVersion 冒充包平台版本。成员沿用现有市场版本校验和内容基线；平台版本标签本身不构成上游内容不可变的保证。

执行不能重新采用上游最新包组成、工作流或其他成员版本。已确认的本地身份、内容、版本或挂载状态若发生影响计划的变化，须重新预览。实现继续满足既有命令预览与实际调用的对应规则。

## 成员解析、复用与冲突

缺失 namespace 的成员仅通过公开接口解析为明确的完整 Marketplace coordinate。身份有歧义、已失效、没有可固定的成员版本或包格式不受支持时，阻止整包安装并列出原因；不猜测来源、不回退到其他成员。

| 当前状态 | 安装行为 |
| --- | --- |
| 成员尚未安装且没有名字或路径占用 | 安装预览确认的版本 |
| 同完整来源的受管成员，Canonical store 内容完整、无本地修改 | 复用当前已安装版本，预览明确显示；不自动升级或降级 |
| 符合复用条件，但缺少部分已选 Agent 挂载 | 保留内容和已有挂载，补齐缺失挂载 |
| 同名不同来源、本地修改、非受管、仅副本、陈旧记录或残留的不完整内容 | 阻止此次安装，提示先在技能管理中处理 |
| 成员之间或入口与成员本地同名，或目标挂载路径存在冲突 | 阻止此次安装并列出具体冲突 |

同一 Scope 共享成员；不同 Scope 的安装与挂载相互独立。复用是显式的包安装能力，不改变普通单技能安装的既有占用规则。

## 工作流适配

官方有效 name 存在时保留，缺失时使用专家包 slug；description 缺失时依据官方名称与摘要补齐。已有身份无效、矛盾、无法解析或发生本地重名时阻止安装。

保留官方流程正文及完整原始文档，添加官方成员引用名到本地原始 Skill name 的对照，并在预览中展示最终入口。适配不改写流程步骤，不改名安装成员，也不将展示名称当作来源身份。原文和最终适配内容都属于已确认快照的证据。

此行为是 [ADR-0032](../../docs/adr/0032-expert-pack-workflow-adaptation.md) 对现有逐字内容校验规则的明确扩展：允许的是入口适配，成员仍沿用原有内容规则。格式与名称对照的检查不等同于所有 Agent 上的工作流效果保证。

## 执行、失败与取消

一次专家包安装由一个后端任务持有整个 Scope 的写入所有权，沿用现有备份、项目身份复验、任务结果、退出与中断恢复约束，不通过前端循环触发相互独立的安装任务。

1. 准备所需下载并校验，确认可复用内容及挂载状态。
2. 所需内容准备完成后逐项发布成员、记录来源和基线并补齐目标挂载。
3. 全部成员及原选中 Agent 的挂载就绪后，才发布或完成工作流入口及其挂载。
4. 记录实际结果，显示专家包完整性、成功项、失败项和未执行项。

准备阶段失败不发布新技能。发布开始后，后续失败保留已经成功写入的内容及实际挂载；未完成的安装关系和结果保持可查看，不能把 CLI 退出成功直接认定为整包成功。入口自身挂载或记录失败也按实际结果显示未完成，不承诺整包原子回滚。

发布阶段沿用 ADR-0021 的失败分类：普通成员失败继续后续成员；备份失败、Scope 失效或失去继续执行的能力时停止后续项。任一成员或必要挂载未就绪都不满足新增工作流的发布条件。

“入口最后发布”约束此次新增或补齐的入口写入；已有独立工作流不会因本次失败而被自动删除、停用或回滚。后续用户独立移除成员时，也只刷新包状态，不自动删除入口。

下载阶段可以取消；发布阶段等待当前技能操作结束后停止后续项。成功结果保留，未完成项可重新预览。应用意外退出后保留已有中断结果和必要备份，不自动续装。

## 补齐安装

完整安装显示「已安装」；未完成安装提供「补齐安装」。补齐必须重新预览，但仍使用原 Pack snapshot 和原 Agent 目标集：

- 缺失成员采用原快照记录的完整来源和具体版本。
- 缺失入口恢复原快照中的最终入口内容，不重新获取上游流程替换它。
- 只补缺失技能和缺失挂载，不重装已经成功且可复用的内容。
- 已有成员后来独立更新、同来源且无本地修改时保留当前版本，明确显示与原快照的差异；不降级、不重写原快照。
- 本地修改、身份冲突或残留不完整内容阻止此次补齐，由用户先处理。只留下陈旧单技能记录时，沿用现有清理记录流程后再补齐。
- 原版本不可获取或必要内容校验失败时明确报错，不替换为最新版本或其他来源。

“补齐缺失”与“覆盖受损占用”不同：前者增加可确定的缺失内容，后者仍受占用与修改规则限制。原始成员身份保持不变，上游成员新增、移除或改名不自动进入旧安装。

## 完整性与单技能管理

完整性与内容差异分开显示。

| 观察 | 展示或操作含义 |
| --- | --- |
| 原目标 Agent 上入口与全部成员齐全 | 完整、已安装 |
| 入口、成员或原目标挂载缺失 | 明确显示缺失项及受影响 Agent；可预览补齐 |
| 成员平台版本不同于原快照 | 版本变化；不将仍存在的成员显示为缺失 |
| 入口或成员存在本地修改 | 显示本地修改，阻止需要干净复用的安装或补齐 |
| 任务失败或中断 | 保留实际完成情况和未完成项，不冒充完整安装 |

成员继续允许独立 Update、Attach、Detach、Remove from Agents 和 Uninstall。移除预览提示所有受影响专家包，完成后刷新它们的观察状态；与包关联不授予额外的文件删除或链接跟随权限。版本变化只更新成员，不改变包快照或声明作者验证过新的组合。

工作流入口支持查看、Attach、Detach、Remove from Agents、Uninstall 和本地修改检测；首版不提供入口的独立上游更新，也将它排除在「更新全部」之外。卸载入口保留成员及包关系，包显示入口缺失。

新增 Agent 通过现有单技能或批量挂载操作完成，用户选中入口与全部成员。额外挂载显示实际状态，原目标集继续用于完整性和补齐；从原目标移除技能后不静默缩减原目标集。首版没有单独的整包挂载操作或包目标编辑流程。

## 忘记与重新安装

「忘记专家包」只删除该包在当前 Scope 的分组和关联，不删除入口、成员、挂载或它们独立的来源记录，也不影响其他包对共享成员的关联。

忘记后从市场安装会生成新的预览。成员按常规复用规则处理；残留入口只有在具备同一专家包的来源记录、与新预览的入口内容及名称对照一致、且无本地修改时才可复用。

若官方入口变化、残留入口被修改或同名来自其他来源，阻止此次安装并说明原因。用户可单独卸载旧入口后重新安装；该路径不隐式覆盖或执行整包更新。工作流保留的来源证据不能依赖已删除的包分组记录。

## 现有架构约束

- [ADR-0029](../../docs/adr/0029-marketplace-catalog-boundary.md)：专家包属于技能市场，不进入 Git 来源发现的订阅、未读和忽略语义。
- [ADR-0030](../../docs/adr/0030-marketplace-installation-records-and-execution.md)：成员完整坐标、确认版本、临时目录校验、原始 Skill name 和应用拥有的来源记录保持有效。
- [ADR-0021](../../docs/adr/0021-batch-operation-lifecycle.md)：整个操作保持一个后端任务和 Scope 所有权，保留成功结果，重新预览后重试。
- [ADR-0031](../../docs/adr/0031-expert-pack-installation-boundary.md)：包快照、共享独立成员、入口最后发布、补齐和忘记的边界。
- [ADR-0032](../../docs/adr/0032-expert-pack-workflow-adaptation.md)：入口适配、原文保留和原始成员名对照。

持久化具体格式、模块组织和内部接口在实现中选择，须满足上述身份、记录独立性和失败可恢复性。官网 pack install 现有行为不能直接替代本规格要求的版本、复用和失败语义；不因官方整包安装命令可用就降低现有边界。

## 验收场景

| 场景 | 可观察结果 |
| --- | --- |
| 浏览、搜索并打开普通包；CLI 缺失 | 可读市场内容；需要 CLI 的安装明确提示依赖 |
| 在全局或项目选择多个 Agent 安装 | 独立 Scope；入口与全部成员挂载到已选目标，现有清单显示包关联 |
| 官方入口缺少字段或成员引用名不同 | 预览展示补齐与对照；安装内容符合确认结果，原文保留 |
| 两个包共享同来源的干净成员，其中一个成员版本较旧 | 同 Scope 复用一份当前版本，保留多个关系，不隐式升级 |
| 已有内容修改、同名不同源、仅副本或残留记录 | 发布前列出阻止原因，现有内容不被隐式覆盖 |
| 成员来源有歧义、版本失效或不支持的组合包 | 详情可读，整包安装被明确阻止 |
| 下载或校验失败 | 不发布新技能，显示失败；已有安装保持实际状态 |
| 成员发布或挂载部分失败 | 成功项保留，未完成项可见；不新增尚不满足条件的工作流 |
| 入口发布、挂载或最终记录阶段失败 | 实际结果和备份可见，不报整包成功，可按缺失项重新预览 |
| 取消、意外退出、任务期间项目迁移或其他写入 | 遵守现有 Scope 所有权和中断规则，不自动续装或越过确认目标 |
| 补齐时上游工作流/组成已变化、某现有成员已独立更新 | 仍采用旧快照；保留干净已更新成员，只补缺失项并显示差异 |
| 原成员版本已不可取得或陈旧记录占用名称 | 不回退其他版本；提示无法补齐或先处理占用 |
| 单独卸载共享成员或移除原目标挂载 | 预览列出受影响包，相关包状态更新；不级联删除入口或其他成员 |
| 更新成员并执行更新全部 | 成员可更新并显示偏离；工作流不被作为上游更新目标 |
| 上游下架或离线 | 本地快照、成员状态和已有本地管理仍可用 |
| 忘记包，再次安装相同或已变化的入口 | 文件与来源记录保留；相同干净入口可复用，变化入口提示处理，不自动覆盖 |
| 通过现有批量挂载加入新 Agent | 实际挂载可见；原补齐目标不被静默替换 |

这些场景已用于后端任务/状态测试、前端预览/结果与回归测试，并在隔离目录执行真实专家包安装、补齐和忘记验证。具体证据与验证边界见 [实施记录](implementation.md)；安装协议验证不等同于 Agent 工作流执行效果验证。

## 事实依据与限制

[官方协议调查](research/01-official-contract.md)记录 2026-11-11 的公开接口、两种 ZIP 格式、版本限制、CLI 目录与失败语义，并与现有代码约束核对。

调查覆盖 54 个中文工作流，其中 30 个缺少标准 name/description；36 个抽样成员中 6 个原始 name 与市场 slug 不同。47 个缺少 namespace 的独立成员 slug 在观察时均能解析为完整坐标，但不能据此承诺未来无歧义。格式观察和名称对照不构成 Agent 运行兼容性验证。
