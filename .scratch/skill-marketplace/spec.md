# 技能市场

状态：已实施并验证。
日期：2026-11-10。
当前交付：原生 SkillHub 市场、受管安装与更新、本地管理和回归验证已完成；详见 [实施与验证记录](implementation.md)。

## 目标与来源边界

新增独立的原生「技能市场」入口，与「发现」并列。用户可在应用内浏览、搜索、查看详情并安装公开 Skill；安装后进入现有按 Scope 划分的受管技能清单。

SkillHub 是首个 Marketplace source，本次只实现 SkillHub。领域与执行边界容纳将来其他市场来源，但本次不提供自定义市场地址、登录、企业私有源或付费获取。

「发现」继续检查与已安装记录关联的 Git 来源，保留既有 Source catalog、未读和忽略语义。公开市场目录不加入这套发现提醒。市场页面明确显示当前来源 SkillHub。

## 页面与浏览

- 进入市场即加载 SkillHub 默认公开列表，沿用平台默认排序；支持分页和关键词搜索。
- 主流程为「列表或搜索结果 → 详情 → 安装确认 → 安装结果」。本次不做独立榜单、分类筛选和收藏。
- 详情展示技能名称、发布者、描述、Marketplace version、技能说明、已声明的运行依赖与官方页面入口。名称和版本的含义遵循下文身份规则；平台没有提供的信息不伪造。
- 使用 Skill 所需的 API Key 等依赖属于 Skill 自身的运行要求，详情展示已知要求；技能安装沿用内容落盘与挂载的定义。
- 当前安装目标可以是 Global scope 或已注册 Project；沿用现有 Scope 选择和多 Agent 选择方式。目录内容与 Scope 无关，已安装状态和冲突按当前 Scope 判断。
- 无 SkillHub CLI 时，浏览、搜索和详情仍可使用。
- 请求失败时保留本次会话上一次成功加载的内容，明确显示失败和重试；不能把旧结果标成新请求成功，也不能把另一查询的旧结果冒充当前查询结果。安装前重新确认选中条目及目标版本可获取。
- 没有可保留结果时显示失败状态；本次不提供离线安装。

## 身份、名称与冲突

Source 可为 Git source 或市场上发布的 Skill。市场身份由 Marketplace source 与其完整 Marketplace coordinate 确定；SkillHub 使用经平台解析的 namespace 与 skill 标识，不凭显示名或裸 slug 猜来源。

本地 Skill 名沿用 `SKILL.md` 声明的原始 `name`，用于技能列表、安装目录与同名冲突判断。发布者、市场来源和市场坐标另外展示，不自动添加发布者前缀，不提供安装时改名。缺少有效声明或不满足现有名称约束时，安装预览应说明无法安装；不能静默生成另一个名字。

同一 Scope 沿用现有同名冲突规则，包括 Managed、Copy-only、Unmanaged 和 Stale lock entry；不同 Scope 可以安装同名 Skill。

| 场景 | 行为 |
| --- | --- |
| 当前 Scope 已安装同一市场条目 | 显示「已安装／查看」，通过现有管理入口处理挂载和更新 |
| 当前 Scope 被其他发布者、其他市场或 Git 来源的同名 Skill 占用 | 提示名称与来源冲突，需要先卸载原 Skill；普通安装不覆盖 |
| 名称被 Stale lock entry 占用 | 沿用现有记录清理或恢复入口，不把它当成可覆盖的空目录 |
| 同名 Skill 只安装在其他 Scope | 不阻止当前 Scope 的独立安装 |

本次保证 Skills Box 发起的市场安装受管，不增加对历史外部 SkillHub CLI 安装的自动接管或迁移。外部安装继续按现有目录扫描规则处理；不能承诺 namespaced 外部目录自动被正确识别。

## 安装与确认版本

1. 从列表或详情选择一个 Skill。本次每次只安装一个市场 Skill，可挂载多个 Agent。
2. 读取完整身份与当前最新 Marketplace version，核实技能说明和原始名称，进行 Scope、名称和 Agent 目标预检。
3. 安装确认页展示来源、发布者、市场坐标、技能名、目标版本、Scope、Agent 和真实执行命令。
4. 用户确认后固定该版本执行。例如确认 `1.2` 后平台发布 `1.3`，仍安装已确认的 `1.2`；目标版本不可获取时提示刷新，不静默改装其他版本。
5. 安装成功后进入受管清单，保存实际请求的平台版本与安装后内容基线，核实内容、记录和挂载结果。

本次不提供历史版本选择、手动降级入口、市场列表多选批量安装或离线安装。安装默认解析最新版本；具体版本在确认后固定，不在执行时重新选择 latest。

安装和更新通过检测到的 SkillHub CLI 获取指定版本；目录与记录适配由应用负责。CLI 会产生 namespaced 子目录及它自己的 lock，不能直接视为现有 Canonical store 中已完成的受管安装。具体持久化文件布局是工程设计，但必须满足下文记录、隔离和核验约束。

## 更新与本地管理

- 本次包含市场 Skill 的 Update check 和用户手动 Update，沿用当前自动检查调度与手动检查入口；不会自动更新文件。
- 根据平台最新 Marketplace version 与安装记录中的版本是否不同判断更新，显示明确的当前版本和目标版本。平台版本按来源定义解释，不把 Git hash 或包内 `_meta` 的版本替代为平台版本。
- **同一版本号下重新上传内容，本次不检测。** 安装后内容基线用于检测本地改动，不作为后台重复下载同版本的理由。
- 更新确认页固定目标版本；执行时适用与安装相同的版本固定规则。没有有效版本信息或上游不可用时显示无法检查或检查失败，不误报为已是最新。
- 更新沿用现有本地改动提示、额外覆盖确认、备份、结果核验和失败处理；CLI 的通用 `upgrade` 不能替代这套确认后执行的流程。
- 更新版本若改变技能自身声明的名称，不自动重命名已有安装；应停止并说明名称变化，需要用户通过卸载和重新安装处理，避免绕过既有身份与同名规则。
- 安装后的内容查看、Attach、Detach、Uninstall 等现有本地管理动作采用适用的 Scope 与路径规则；市场 Skill 卸载由应用执行，无须 SkillHub CLI。已有批量管理动作沿用各自的范围、资格和结果规则，本次没有新增批量安装。
- 上游条目下架或不可访问不会自动删除本地 Skill；本地管理继续可用，更新检查报告实际失败原因。

## CLI 检测与提示

| 操作 | SkillHub CLI 缺失或不可用时 |
| --- | --- |
| 市场浏览、搜索、详情 | 可用，仍受网络请求结果约束 |
| 市场 Skill 检查更新 | 可用，通过只读来源接口查询 |
| 市场 Skill 安装、更新 | 阻止执行并提示依赖问题 |
| 已有市场 Skill 内容查看、挂载、卸载等本地管理 | 可用，仍检查本地路径与记录状态 |
| Git 来源操作 | 继续由其自身依赖决定，不被 SkillHub 依赖状态禁用 |

安装或更新时缺少 CLI，提供安装命令、官方说明和「重新检测」，由用户自行安装。引导使用官方 CLI-only 安装方式，避免把完整 OpenClaw 配置作为本功能的依赖。检测到路径但不能执行、所需运行时缺失或能力不兼容时，应显示真实原因，不能统一误报「未安装」。

CLI 路径解析、版本与能力检测、环境控制、超时及重新检测由实现负责。市场来源必须保持为所展示的 SkillHub 官方公开来源，不能因用户 CLI 的其他源配置而把同一坐标解析到另一个服务。

## 安装记录与执行约束

以下是已确认产品行为对应的工程约束，不引入额外产品流程。

- 市场安装记录由 Skills Box 按 Scope 管理，保存本地名、Marketplace source、完整坐标、确认请求的 Marketplace version、安装内容基线及适用的路径/时间信息；统一投影为领域上的 Lock entry 和 Managed skill。
- 市场记录与 Git CLI 管理的 lock 隔离，不能伪造 `github/git/gitlab` 来源。具体文件格式须兼容既有 Git 读写，并在操作后验证未改动无关记录。
- CLI lock/JSON 的版本及 ZIP 内 `_meta` 仅作为辅助信息；既有调查已发现它们可能与实际请求的平台版本不同。成功至少须核对请求坐标与版本、CLI 结果、实际目录和 `SKILL.md`，再记录安装后内容基线；不能只信退出码，也不能声称本地指纹能证明上游版本内容不可变。
- 使用操作隔离的临时目录接收 CLI 结果，核验后发布到规范的 Canonical store 并创建 Agent attachment。`@namespace/slug` 的 CLI 目录布局不能直接泄漏为本地安装名。
- 复用 Mutation task、单写者、Project 身份检查、Mutation surface、Backup snapshot、取消窗口和结果核验。CLI 暂存阶段失败不得破坏已有安装；进入真实写入阶段后的失败按现有协议保留备份和实际结果，不承诺整批自动回滚。
- 市场真实 CLI 命令沿用 ADR-0026 的后端生成、预览与实际执行一致性、实际调用记录；原生本地动作不展示虚构命令。
- 恢复技能、清理记录以及复制到项目等现有入口遇到市场来源时，必须按来源分派或明确显示当前资格，不能错误转交 Git CLI。涉及重新获取内容的恢复采用市场安装的 CLI 依赖与版本规则；这不增加外部安装接管能力。

## 验收场景

1. 无 SkillHub CLI 时可以加载默认列表、分页、搜索和查看详情；点击安装得到依赖提示，重新检测可恢复安装，Git 安装不受影响。
2. 正常安装到全局和已注册项目，分别核验规范目录、市场记录和所选 Agent 挂载；页面可查看和管理安装结果。
3. 不同 namespace 使用相同显示名时可以区分来源；同 Scope 同原始技能名安装被拦截，不同 Scope 可以独立安装。
4. 已安装相同坐标显示已安装；普通安装不会覆盖 Managed、Unmanaged、Copy-only 或 Stale record 占用的名称。
5. 确认目标版本后 latest 改变，CLI 仍请求确认版本；目标版本消失时明确失败。CLI JSON 误报 latest、ZIP `_meta` 与平台版本不同也不会污染平台版本记录。
6. 最新平台版本变化时出现更新候选；同版本内容重传不触发检测。本地修改按现有覆盖确认和备份规则处理。
7. 缺少 CLI 时仍可检查更新、查看、挂载和卸载市场 Skill；市场更新得到对应依赖提示。
8. 网络失败保留与原查询对应的已加载结果，显示失败和重试；分页/搜索的过期响应不替换当前查询结果，缓存结果不能绕过安装前的条目核实。
9. CLI 下载、内容校验、目录发布或挂载失败均提供真实结果；暂存失败保留原安装，写入失败保留所需备份；重试沿用既有预览与确认规则。
10. 市场 Skill 在项目不可用、Relocate/Forget、同名外部目录出现或记录损坏时遵守既有 Scope 与变更检查，不把未完成核验当作安装成功。
11. 验证现有 Git 安装、更新、发现、受管清单和批量管理没有因市场来源记录或依赖隔离而退化。

以上场景已通过自动化、浏览器预览及官方 CLI 临时 HOME 集成验证。具体覆盖、命令、结果与验证边界见 [实施与验证记录](implementation.md)。
