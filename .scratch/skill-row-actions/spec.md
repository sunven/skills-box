# 技能表格操作列

Implementation: complete

## 已确认的需求

- 在技能表格最右侧增加「操作」列，提供每个技能的常用操作。
- 需求来自 2026-11-04 的全局技能列表截图。
- 全局和项目的技能列表都增加操作列，各操作针对当前 Scope 的技能。
- 直接展示「打开目录」「更多」；只有存在可更新版本时直接展示「更新」。
- 「更多」包含查看内容、检查更新、管理 Agent 挂载、卸载。
- 按钮常驻显示，采用图标与悬停提示控制宽度；卸载放在菜单末尾。
- 「打开目录」直接打开 Finder；「查看内容」打开详情内容页；「管理 Agent 挂载」打开详情挂载区域。
- 「更新」「卸载」沿用现有确认弹窗、本地改动确认、备份及执行校验；点击行的其他区域仍打开默认详情。
- 不可用的菜单项保留并置灰，展示具体原因；沿用现有管理状态和挂载资格限制。
- 打开目录失败或副本路径有歧义时展示原因；执行中禁止重复触发。
- 窄窗口优先保留名称、状态、操作列，先收起来源与 Agent 挂载列；名称和描述截断，操作列位置固定。

## 现有行为与约束

- 全局与项目共用列表组件；项目技能身份为 Scope 与技能名称，所有读写必须携带当前 Scope 和技能 ID。
- 详情已有更新、卸载确认弹窗；本地改动确认、备份和校验流程已经存在。
- Managed skill 可检查更新，有更新候选时可更新；Managed skill 和 Copy-only skill 可卸载，Unmanaged skill 不可更新或卸载。
- 挂载与断开已有详情入口与可用规则；断开只针对一个 Agent attachment，卸载针对整个技能。
- 打开目录 API 解析真实路径；Copy-only skill 的多个副本路径可能有歧义，不能随意选择其中一个。
- 列表行当前整体为按钮；操作列应提供独立的点击与键盘目标。

## 完整交互规格

### 直接操作

操作列置于状态列之后，表头为「操作」。目录、更新、更多使用独立图标按钮，并提供可访问名称、焦点样式和悬停提示。

- 打开目录：使用当前 Scope 和技能 ID 打开服务端解析的目录，不额外打开详情。
- 更新：仅在当前技能存在更新候选时展示，进入现有单技能更新确认弹窗。
- 更多：展开对应技能的菜单。

### 更多菜单

菜单顺序为查看内容、检查更新、管理 Agent 挂载、分隔线、卸载；卸载使用危险动作颜色。

| 操作 | 行为 | 不可用规则 |
| --- | --- | --- |
| 查看内容 | 打开当前技能详情的内容页 | 沿用内容浏览器现有读取限制与错误反馈 |
| 检查更新 | 只读检查当前技能 | 仅 Managed skill 可用；检查运行中禁止重复触发 |
| 管理 Agent 挂载 | 打开详情挂载区域，使用已有挂载与断开入口 | 沿用详情现有管理状态、目录状态与 Agent attachment 资格限制 |
| 卸载 | 打开现有卸载确认弹窗 | Managed skill 与 Copy-only skill 可用，Unmanaged skill 禁用 |

不可用项的具体原因以提示呈现，不能仅通过颜色区分。打开目录无法提前判断的失败，包括多个副本路径的歧义，使用 API 的实际错误反馈，不擅自挑选目录。

### 范围与布局

- 全局和项目列表共用同一操作列，操作目标始终为触发时的 Scope 与技能 ID。
- 点击操作不触发行选择，键盘可以分别聚焦行入口和操作按钮，不能产生嵌套按钮。
- 操作列与名称、状态在窄窗口持续可见，表头和行内容对齐。

## 已确认的交互细节

以下细节已随完整方案确认：

- 没有更新按钮时不保留占位，目录与更多按钮直接相邻，按钮间距为 4px。
- 菜单选择后、点击外部、按 Escape 或切换 Scope 时关闭；支持键盘操作和焦点返回。
- 打开目录或检查更新时显示进行中状态，并防止重复触发；只读操作失败在列表附近显示可关闭的提示，包含技能名称和原因。更新、卸载继续使用现有弹窗的进度与结果反馈。
- 只增加现有操作的入口；源仓库链接、直接编辑、批量动作不在本次范围。

## 验收条件

- 全局和项目的表头最右侧出现「操作」，按钮常驻且各行对齐。
- 打开目录触发正确 Scope/技能的 API；点击该按钮不会同时打开详情。
- 只有更新候选显示更新按钮，并打开既有确认流程。
- 更多菜单的各入口到达正确内容页、挂载区域或确认弹窗，不可用项有明确原因。
- 未受管与仅副本技能遵守既有能力边界；本地改动确认、备份和卸载校验仍生效。
- 目录歧义、目录不可用、检查失败和重复触发具有可理解的反馈。
- 窄窗口保留名称、状态、操作；菜单不被列表滚动区裁切，键盘可完整操作。
- 切换 Scope 后不保留旧菜单，也不将旧目标的后续状态呈现到新 Scope。

## 讨论状态

完整方案已确认并实现，验证记录见 [verification.md](verification.md)。此次设计复用现有领域概念与行为，没有需要补充的领域术语，也没有符合 ADR 条件的架构取舍。
