# skills.sh 市场来源

Status: implemented and verified; pre-existing verification exceptions recorded in implementation.md.

日期：2026-11-14。
设计访谈 Q1–Q11 及整体规格均已由用户确认。实现、前端与 Rust 回归、浏览器检查和隔离的全局／项目真实 Git 安装验证已完成；结果与既有检查例外见 [实施与验收记录](implementation.md)。

## 目标与已确认决策

1. **完整流程（Q1）**：在技能市场中切换到 skills.sh，搜索技能、查看详情，并在当前全局或项目范围内完成安装；保留现有 SkillHub 市场来源。
2. **安装身份（Q2）**：skills.sh 作为目录来源；对于指向 GitHub 的条目，实际安装使用该 Git 仓库。已从 Git 入口安装的同仓库、同技能应被识别为同一安装身份，并沿用 Git 更新与来源发现规则。
3. **接口（Q3）**：首版接受直接使用 skills.sh 官网的匿名接口，并承担接口变化时的适配成本；接口失败时提供明确错误和重试／官网入口。
4. **来源切换（Q4）**：首次默认 SkillHub；记住用户上次选择的来源；会话中分别保留各来源的搜索条件和列表位置。
5. **安装范围（Q5）**：首版仅支持明确指向公开 GitHub 仓库的条目在应用内安装。独立网站等其他来源条目保留浏览与官网入口，明确标注暂不支持安装。
6. **浏览范围（Q6）**：提供累计榜、24 小时趋势榜、热榜及关键词搜索。搜索保留上游结果顺序，最多展示接口返回的 200 条并提示上限。skills.sh 首版不接入分类、API Key 筛选、专家包、专题或审计信息；安装量标注对应榜单的时间范围，不映射为 SkillHub 下载量。
7. **详情内容（Q7）**：展示市场身份、仓库、安装统计与 SKILL.md，保留概述和只读文件浏览。内容标明来自 skills.sh 快照；快照可能缺失或不完整，不宣称是 Git 上游当前完整内容。快照缺失时说明原因并提供官网入口，不将其解释为技能没有文件。
8. **安装内容（Q8）**：沿用现有 Git 默认分支安装，不固定市场快照或 Git commit。安装确认页说明实际安装内容可能与市场快照不同；不对预览到执行之间的上游内容不变作保证。
9. **单技能安装（Q9）**：只安装当前市场条目对应的一个技能。Git 预览必须按技能名唯一匹配；缺失、改名、重复名称造成歧义或预览无法解析时，阻止本次安装并说明原因，不自动改装其他技能，也不提供同仓库其他技能的附带勾选。
10. **快照缺失（Q10）**：明确的 GitHub 仓库与技能名足以进入 Git 预览；市场快照缺失不单独阻止安装。是否能继续由 Git 预览、本地环境、当前 Scope、冲突和 Agent 目标检查决定。
11. **入口层级（Q11）**：仅在现有“技能”页签内提供 SkillHub／skills.sh 来源切换；“专家包”页签继续明确属于 SkillHub。

## 页面与浏览行为

主流程是“技能市场 → 技能 → 选择来源 → 榜单或搜索结果 → 市场详情 → 单技能安装确认 → 安装结果”。当前 Global scope 或已注册 Project 决定安装目标；浏览目录与 Scope 无关，已安装状态和冲突跟随当前 Scope。

- 首次使用默认 SkillHub，后续启动恢复上次选择的技能市场来源。在同一应用会话内，各来源分别保留搜索词、榜单／筛选、页位置和列表滚动位置；详情返回列表恢复原位置。进入 SkillHub 专家包不改写技能页记住的来源。
- SkillHub 保留现有目录、筛选、详情、文件浏览、安装及专家包行为。skills.sh 仅展示已确认支持的能力，不将 SkillHub 的筛选条件或版本字段套到 skills.sh 上。
- skills.sh 无关键词时展示累计榜、24 小时趋势榜或热榜，按上游顺序浏览后续结果；有关键词时使用独立搜索结果及上游排序，不假称是对全榜单做了本地筛选。清空关键词可回到所选榜单。
- 搜索满足接口的至少两个字符要求；最多显示返回的 200 条。界面区分“本次返回多少条”与“全平台共有多少条”，达到上限时提示缩小搜索范围；不提供伪造的全量搜索分页。
- 卡片展示可获得的技能名、来源标识、安装量和安装状态。匿名目录缺少描述、版本、收藏数等字段时省略或明确表示未提供，不为补齐卡片逐项下载所有技能内容。
- 安装量保持其榜单时间范围。目录接口的 total 只表示该接口可浏览范围，不宣传为平台完整收录数量；缺失统计值不当作零。

## 市场详情与内容快照

详情明确展示“收录于 skills.sh”、条目身份、可确定的实际仓库、适用的安装统计及官网入口。GitHub 仓库与独立网站来源按各自真实标识展示，不把域名拼成 GitHub 仓库。

- 概述展示可用的 SKILL.md；文件页签只展示本次 Marketplace snapshot 实际返回的文件。内容沿用现有只读 Markdown／文本预览规则，不执行其中的脚本或指令。
- 标明“市场内容快照”，说明它可能与上游当前内容不同，文件列表可能不完整。快照 hash 只用于识别浏览内容，不显示为 Marketplace version、Git commit 或已安装版本。
- 同一次详情阅读的概述和文件属于同一份快照，不能将旧文件列表与另一次刷新的文件内容混合。刷新失败保留旧内容时需明确标记失败；无可用内容时显示缺失或加载错误、重试和官网入口。
- 快照缺失不等于上游技能不存在。可安装的 GitHub 条目仍可发起 Git 预览；独立网站或无法确定 Git 安装来源的条目显示暂不支持应用内安装，保留已有元数据与官网入口。

## 安装身份、选择与确认

Marketplace coordinate 标识 skills.sh 的目录条目，Git source 与技能名标识其安装目标。保留目录的 source、skillId 与 name 等不同概念；不把市场 URL slug 当成 Git 仓库路径，也不把目录身份写成新的 skills.sh 安装来源。

1. 对明确指向公开 GitHub 仓库的条目发起现有 Git 只读预览，使用目录提供的技能名寻找唯一匹配项；沿用现有不区分大小写的匹配规则，以预览中实际名称构造安装请求。
2. 唯一匹配失败时停止，并提供重新预览与官网／仓库入口。不得根据相似名称或另一路径猜测安装对象。
3. 匹配成功后只确认该一个技能及目标 Scope、所选 Agents、仓库和实际执行命令，不展示额外技能选择或“全选仓库”。
4. 确认页说明按 Git 默认分支获取内容，实际安装可能不同于当前市场快照。确认的是安装来源、技能选择和命令，不承诺固定 Git commit 或快照内容。
5. 执行复用现有 Git Mutation task 与结果核验，安装后进入当前 Scope 的 Managed skill 清单；更新、挂载、卸载、恢复、复制到项目及 Source discovery 沿用适用的 Git 规则。

如果预览之后仓库内容变化，仍遵循既有 Git 执行语义与失败核验。不得为实现市场快照一致性而改用缓存快照落盘，也不得静默改装其他技能。

| 当前 Scope 状态 | 结果 |
| --- | --- |
| 同 Git source、同技能已有实际安装 | 显示已安装／查看，不重复创建市场安装记录；从其他入口安装也适用 |
| 同名技能来自 SkillHub、其他仓库或未受管目录 | 明确同名冲突，沿用先处理原安装的规则；不覆盖、不自动改名、不按名字合并来源 |
| Stale lock entry 占用名称 | 使用现有恢复／清理入口，不显示为可直接覆盖的空目录 |
| 同名技能只在其他 Scope | 不阻止当前 Scope 独立安装 |
| Git 预览缺失、重名歧义或解析失败 | 阻止本次安装，保留目录信息和重新尝试入口 |

## 依赖与失败

| 情况 | 行为 |
| --- | --- |
| 本地 Git 安装依赖缺失 | 榜单、搜索和快照读取仍可用；Git 预览／安装显示现有依赖问题与重新检测入口 |
| SkillHub CLI 缺失 | 不影响 skills.sh 的 Git 安装资格判断 |
| 榜单或搜索失败 | 保留同一市场来源的上次成功结果并注明旧查询条件和错误；无旧结果则显示错误；提供重试与官网入口 |
| 快照加载失败，但 Git 预览成功 | 明确内容读取失败，仍可按正常确认流程安装 |
| Git 预览失败，但市场快照可用 | 保留只读内容，阻止安装，不使用市场快照绕过失败 |
| 本地清单不可读、项目失效、目标或冲突变化 | 沿用既有 Scope、记录与写前复验规则；市场目录成功不能替代本地资格检查 |

不同来源及查询的缓存、旧结果和过期响应必须隔离，不静默切换市场。已安装技能的 Git 更新不依赖 skills.sh 目录是否仍可访问，市场下架不自动移除本地技能。

## 工程边界

以下是上述产品行为及既有规则对应的实现约束，不增加产品流程：

- 新增 skills.sh 目录适配并为来源及其能力分派必要请求；不要求构建用户可配置的任意市场插件系统。
- skills.sh 使用官网匿名接口，不引入 Vercel 服务端代理、账户或令牌设置；接口形状与匿名访问能力可能变化，需按已接受的维护边界隔离适配并真实报告失败。实测接口与限制见下方调研。
- SkillHub 仍按平台版本与独立市场记录安装；skills.sh 的 GitHub 条目使用 Git 安装记录，不迁移现有 SkillHub 或 Git 安装，也不保存冒充 Git 版本的市场快照 hash。
- 安装确认、实际命令、Scope 与 Agent 目标遵循既有命令预览、单写者、备份、取消窗口、冲突复验及结果刷新规则。
- 复用现有 Discovery 安装能力时，去除该入口不适用的“附带选择其他技能”及预览失败即使 Discovery source 失效的副作用。
- 市场目录本身不进入发现的未读／忽略生命周期；成功的 Git 安装按现有规则使其仓库成为 Discovery source。
- 不新增非 GitHub 安装协议、skills.sh 网页链接导入、批量市场安装、固定历史提交或离线安装。skills.sh 专家包、专题、审计及额外筛选均不在首版范围内。

## 验收条件

1. 首次进入技能市场默认 SkillHub；选择 skills.sh 后重启仍恢复该选择。会话内往返来源及详情，分别恢复查询和列表位置；专家包始终明确属于 SkillHub。
2. skills.sh 三种榜单可浏览后续结果，安装量具有正确时间含义；搜索保留上游顺序并明确返回上限，不把榜单窗口或搜索条数当作全平台总量。
3. GitHub 与独立网站条目均能展示来源和官网入口；仅明确的公开 GitHub 条目提供应用内安装。非 GitHub 来源不会被错误解析或传入 Git 安装器。
4. 详情正确展示可用 SKILL.md 和快照文件；缺失、不完整、刷新失败及文件不存在有明确状态。快照内容不会被说成 Git 当前完整内容或平台版本，刷新不会混用不同快照。
5. 在隔离的测试 Global scope 与 Project 中完成单技能安装；确认页显示真实仓库、技能、Scope、Agents、命令及快照差异提示。核验 Git 安装记录、实际技能目录、Agent 挂载和结果刷新。
6. 一个仓库包含多个技能时，市场操作只安装所选条目；预览缺失、改名、多个同名匹配或无法解析时阻止安装，不改变 Discovery history，也不安装其他条目。
7. 快照接口失败而 Git 预览成功时仍可安装；反向场景只能浏览，不能用缓存快照绕过 Git 失败。预览到执行之间内容变化不应被错误宣称为固定快照安装。
8. 直接从 Git 入口安装的同仓库、同技能在 skills.sh 中识别为已安装；同名不同来源、Unmanaged、Copy-only 与 Stale lock entry 沿用对应冲突／恢复规则。其他 Scope 的安装不产生当前 Scope 的错误阻挡。
9. 无本地 CLI 时目录和快照仍可读；缺少 Git 依赖仅阻止 Git 预览和安装，缺少 SkillHub CLI 不误伤 skills.sh。独立模拟目录请求失败，已有 Git 安装仍使用既有更新与本地管理能力。
10. 搜索、翻页、来源快速切换及失败回退不显示另一来源或错误条件的结果；旧数据明确标记，重试成功后正常恢复。
11. Project 切换、Relocate／Forget、本地清单不可读、外部同名目录出现及安装失败遵循现有目标与写入协议，不能把安装结果刷新到错误的 Scope。
12. 回归 SkillHub 的筛选、版本详情、文件浏览、固定版本安装／更新与专家包；回归 Git 直接安装、发现安装、更新及批量管理，不改变其原有选择范围或来源语义。
