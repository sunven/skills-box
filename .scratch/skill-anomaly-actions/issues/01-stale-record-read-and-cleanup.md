# 01: 完整失效记录清单与定向清理

Status: resolved
Blocked by: None
Parent: [spec.md](../spec.md)

## What to build

提供当前 Scope 的完整 Stale lock entry 清单与清理资格。不要把库存摘要中的三个示例作为完整目标，也不要把容错扫描的空结果当作安全删除依据。严格区分不存在、目录占用、链接、不可读、扫描不完整和不可用项目。

实现受限的原生记录清理：在应用单写许可与 Scope 身份下，备份 Lock 原文和对应 Baseline fingerprint；仅删除确认的失效 `skills` 键，保留未选中记录和未知字段。Global v3 与 Project v1 使用严格解析，写入前检查当前文档、目标状态及项目根，通过同目录原子替换发布并保留权限。检测到外部变更要求重新预览。

清理无需 CLI 或网络。成功移除相应基线与检查结果；关联基线清理失败需准确报告已清理记录和警告。复用既有 Scope、备份、错误分类和原子文件工具，避免新增通用 Lock 编辑接口。

## Validation

临时 AppPaths 覆盖全局/项目隔离、完整扫描、未知字段保留、备份失败零写入、写入失败、预览后目录或 Lock 变化及无需 Node 的清理。验证涉及普通文件、目录、副本和悬空链接的目标均不能当作可清理记录。
