# 失效安装记录的清理与技能恢复

Status: resolved
Design: approved
Implementation: complete
Validation: passed
Date: 2026-11-05

## 目标

异常弹窗已能报告 Stale lock entries，但用户不能在应用内处理这些残留安装记录。为它们提供明确的「清理记录」与「恢复技能」操作。

## 已确定的范围

- 本轮只处理 Stale lock entries。断链修复、本地改动处理、源路径缺失处理等其他异常另行设计。
- 「清理记录」删除已无对应 Skill 文件的安装记录。
- 「恢复技能」依据 Lock entry 的 Source 重新安装缺失的 Skill。
- Global scope 与已注册 Project scope 都支持上述操作。
- 每次操作限定在当前 Scope，不修改其他 Scope 的记录或 Skill。

## 清理资格

- 当前 Scope 必须可用，Lock 可读且版本受支持。
- 必须能完整扫描当前 Scope 的 canonical store 与 Agent 目录，确认目标没有任何 Skill 目录、副本或挂载。
- 项目不可用、权限不足、目录解析异常或扫描不完整时，不能把「无法判断」当成「不存在」，禁用清理并展示原因。
- 预览后的状态不构成永久资格。执行前再次验证目标仍是 Stale lock entry；出现了目录或挂载就停止该目标的处理。
- 清理只删除选中的失效安装记录，不删除 Skill 文件或 Agent attachments，不修改其他 Lock entries。

## 恢复来源与目标

- 使用 Lock entry 记录的 Source。记录中有安全、有效的 ref 时，按该分支或标签恢复；没有 ref 时，使用来源的当前默认分支。
- 「恢复技能」是重新安装来源当前指定分支或标签上的内容，不承诺回到原安装时的精确版本。现有 Lock entry 的文件夹指纹不能单独定位那次安装的提交。
- 恢复预览展示 Source、ref 和当前 Scope。
- 现有安装记录没有保存原来的 Agent 挂载集合，因此不猜测历史挂载关系。
- 默认只恢复当前 Scope 的 canonical store；用户可自行勾选当前 Scope 中可选的 Agent targets，追加挂载。

## 恢复名称与不可恢复条目

- 在原 Source 的指定 ref 或默认分支中按记录的 Skill 名称查找，不把旧 skillPath 当成不可改变的身份。
- 同名 Skill 移动了目录时，允许从新路径恢复，并更新这条安装记录。
- Skill 已改名、删除，Source 不可访问或无法解析时，保留原 Lock entry，明确展示不能恢复的原因。
- 不自动换成其他 Source 的同名 Skill。用户可以重试，或另行选择「清理记录」。

## 入口与选择

- 在异常弹窗的「失效 lock 条目」卡片增加「处理」入口。
- 展示当前 Scope 的完整 Stale lock entry 清单，不限于现有的三个示例。
- 清单展示名称与 Source，支持逐项勾选和全选，默认不勾选任何记录。
- 「清理记录」与「恢复技能」是两个独立动作，一次只执行其中一种。
- 选择与动作均限定当前 Scope。
- 清单明确显示当前 Scope 与选中数量。预览前切换 Scope 时清空选择，关闭旧 Scope 的处理界面。
- 恢复的 Agent 选择对本次选中条目统一生效，默认全部未选；canonical store 始终是恢复目标。
- 清单中的不可执行条目保留可见，分别说明清理或恢复被禁用的原因。没有可执行项时禁用最终提交。

## 关联记录

- 清理成功后，移除选中条目的 Baseline fingerprint 和对应的更新检查结果。
- 清理前备份 Lock 与对应的 Baseline fingerprint；保留 Skill 文件和 Agent attachments。
- 保留 Source discovery 的已读、忽略与目录历史。
- 如果某个 Source 在所有 Scope 都已没有安装记录，按现有发现规则停止跟踪该 Source，保留发现历史。

## 预览与确认

- 两种动作都先展示预览，再确认执行。整批确认一次，不逐项重复确认。
- 预览列出 Scope、完整的选中条目、可执行项与跳过项及各自原因。
- 清理预览明确列出将修改的 Lock 与关联基线，以及「仅清理安装记录」的含义。
- 恢复预览列出 Source、ref、匹配到的 Skill、canonical 路径和用户选择的 Agent targets。
- 最终按钮分别为「清理 N 条记录」与「恢复 N 个技能」，N 仅计入本次可执行条目。
- 提交后固定本次 Scope、动作、Skill 名称与 Agent targets，执行期间禁止扩大选择或切换 Scope。
- 预览是服务端生成的有版本计划。执行前验证计划和当前状态一致；变化的条目跳过，要求重新预览。

## 执行、失败与备份

- 单项与批量都通过同一注册 Mutation task 执行。整批持有应用现有的单写许可与 Scope，逐项串行执行。
- 普通单项失败后继续处理其他条目；备份失败、Scope 失效、Lock 损坏或检测到无法安全继续的状态变化时停止整批。
- 提供「停止后续操作」。当前正在写入的条目完成并校验后停止，其余可执行条目标为未执行，不强制中断当前写入。
- 已成功完成的操作保留，不自动回滚；异常退出沿用中断记录，不自动继续执行。
- 每个目标写入前备份当前 Scope 的 Lock 原文和该目标已有的 Baseline fingerprint。结果中提供备份位置和「打开备份目录」。
- 本轮不增加一键撤销，备份供手动恢复；恢复技能和恢复备份是不同概念。
- 结果逐项显示成功、失败、跳过、未执行，以及原因和已有备份位置。
- 重试只包含失败或未执行项，重新生成预览并确认，不能重新执行成功项或自动包含新条目。
- 写入开始前的来源解析、名称匹配或网络失败保留原安装记录。CLI 写入后失败可能留下部分文件或记录，展示核实后的实际状态和备份，不声称已自动恢复原状；重试仍重新核对资格，不覆盖外部新增的技能。
- 安装记录已清理成功但关联基线清理失败时，展示清理成功及关联记录警告，不把已删除记录误报为未执行。保留备份，不因重试再次删除成功项。

## 工程边界

### 完整检查与目标身份

- 完整清单直接读取当前 Scope 的 Lock；现有异常计数及三个示例继续作为摘要，Stale lock entries 不加入已安装主列表。
- 清理资格不能仅依赖容错库存扫描的空结果。检查当前 Scope 认可的 canonical、catalog Agent 与 Extra agent 目录，并区分不存在、不可读、异常路径和不完整解析。
- 已存在的 Agent skills 目录不能仅因 Agent 检测结果为空而被忽略；目录范围沿用已有 Scope 布局，不能扩大到任意未注册路径。
- 任何同名目录、普通文件、链接或副本占用都不构成可清理目标；断链仍由既有异常分类处理。
- 项目不可用、重新定位或遗忘使旧预览失效。写入前核对项目身份、根目录和当前 Lock，项目路径不得逃出 Project root。

### 定向清理 Lock

- 为记录清理新增受限的原生写入边界，作为 [ADR-0001](../../docs/adr/0001-cli-mutations-native-reads.md) 的明确例外，见 [ADR-0027](../../docs/adr/0027-stale-record-cleanup-boundary.md)。Install、Update 与现有 Managed Uninstall 继续使用 CLI。
- 支持当前 Global v3 与 Project v1 Lock。必须先通过现有严格解析；损坏或不支持的版本拒绝变更。
- 从原始 JSON 文档仅删除本次确认的 `skills` 键，保留所有未选中条目的原值以及顶层和条目内的未知字段，不从规范化 `LockEntry` 重新构造整个文档。
- 拒绝不安全的 Lock 路径和非常规文件；项目 Lock 与临时文件必须保持在当前项目内。用同目录临时文件和原子替换，保留原文件权限。
- 写入前重新读取并比较预期 Lock 内容。检测到外部修改则停止，要求刷新预览；每次成功写入并验证后推进本任务的预期状态，不能把本任务上一项的写入当作外部变更。
- 原子替换防止应用产生半份 JSON；应用许可和内容重检不构成对不遵循应用协议的外部进程的跨进程事务保证。
- 清理无需 Node、npx、Git 或网络。UI 和后端以该动作所需能力判断资格，不因恢复所需的 CLI 环境缺失而禁用清理。

### 恢复执行

- 复用已有 Source/ref 解析、只读来源预览、Agent target 校验、`skills@latest add` 执行及安装后的实际路径和 Lock 校验。
- 按原 Source 的同名 Skill 匹配；出现歧义时要求重新预览，不进行模糊猜测。缺少旧 skillPath 或版本指纹本身不妨碍来源中同名 Skill 的恢复。
- 不支持的 Source 类型或缺少所需 CLI 工具时禁用恢复并解释原因，不妨碍符合资格的记录清理。
- 恢复使用专用的 Stale lock entry 授权：只允许当前 Scope 中本次确认、写入前仍失效的同来源同名记录。不得把现有 InstallRequest 的宽泛 `retry` 当作恢复授权，或覆盖已有 Managed、Copy-only、Unmanaged 技能。
- 写入后核对指定名称的 canonical、用户选择的 Agent attachments 与 Scope Lock，确认成功后记录新的基线。
- 同源同 ref 的只读预览可以复用，实际目标仍逐项执行，不通过前端循环单项 IPC 释放整批许可。

### 界面与刷新

- 复用既有 Mutation surface 的进度、错误、结果、停止、备份与重试能力，扩展现有 Fake backend 的真实状态变更语义。
- 更新异常弹窗中过时的「v1 只读」「不提供一键修复」及反对批量操作的描述，使文案与新功能一致；操作界面使用清理记录和恢复技能的术语。
- 每次结束后刷新当前 Scope 的库存、异常计数和完整失效记录清单；成功清理的条目移出清单，成功恢复的 Skill 出现在该 Scope 的已安装列表。
- 更新报告只移除或更新受影响条目，保留其他 Skill 和 Scope 的结果；恢复成功后为新 Skill 生成与实际安装相符的状态，不能让整张列表回到「未知」。
- 刷新 Source discovery 关联，沿用已有来源停用与历史保留行为。

## 验收清单

1. 截图中 21 条记录能打开完整清单；默认未选；单项与全选可分别清理或恢复，最终数量与预览的可执行目标一致。
2. Global 与两个 Project 中同名条目的预览、执行、基线、更新结果和异常计数完全隔离。
3. 清理只删除确认的失效键和关联基线；未选中记录、顶层未知字段、条目内未知字段和任何 Skill 文件均保留。
4. 缺少 Node/Git 或离线时仍能清理；恢复展示对应的工具或来源不可用原因。
5. 任何目录、文件、链接、副本重新出现，或者扫描不完整、权限失败、项目不可用，都不能被误判为不存在并清理。
6. 备份包含 Lock 原文与原基线；备份失败零写入；临时写入或原子替换失败时原 Lock 保持可解析且未被部分覆盖。
7. 预览后 Lock 变化、项目变化或目标出现，执行拒绝或跳过并要求重新预览；应用自身前一条成功写入不使后一条误失效。
8. 原 Source 中同名 Skill 移动目录后可恢复；有 ref 使用原 ref，无 ref 使用默认分支；默认只恢复 canonical，手选 Agent 才追加挂载。
9. Source 不支持、不可访问、Skill 改名/删除或同名歧义时，写入前明确失败并保留记录；不跳转到其他 Source 的同名 Skill。
10. Restore 不使用宽泛 retry 绕过已有技能冲突；CLI 成功退出还须实际路径、名称、挂载和 Lock 验证通过。
11. 普通单项失败继续；备份失败或不能安全继续停止；停止后续操作等待当前项完成，其余标未执行。重试重新确认且不重放成功项。
12. 基线清理失败和 CLI 部分写入失败准确展示实际状态、警告与备份；不伪装成已回滚或全部成功。
13. 清理或恢复后异常计数和对应列表同步更新，其他 Skill 的更新状态与发现历史保留。
14. 前端 Fake backend 集成测试、后端临时 AppPaths 测试和必要的隔离 CLI 沙箱验证覆盖上述行为；所有变更验证使用临时数据，不处理用户真实的 21 条记录。

## 现有约束

- [ADR-0001](../../docs/adr/0001-cli-mutations-native-reads.md) 当前规定 Lock 由 CLI 写入，执行选择器现为 `skills@latest`。本设计提议为原生定向记录清理增加受限例外，见 ADR-0027；不改变 CLI 安装与更新的所有权。
- [ADR-0011](../../docs/adr/0011-project-scope-registry.md) 定义按 Scope 隔离的 canonical store、Lock 和 Agent attachments。
- [ADR-0025](../../docs/adr/0025-selective-agent-removal.md) 有意让 Remove from Agents 保留 Lock entry，包括移除最后一个副本后的 Stale lock entry。本功能提供后续显式处理，不改变 Remove from Agents 的含义。
- 沿用仓库已有的变更约束：变更串行执行、写入前备份、执行后核实；备份失败就不开始写入。恢复继续使用当前统一的 CLI selector，不另设版本策略。
- 本轮访谈只记录已确定的设计；共享理解确认后才进入实现。
