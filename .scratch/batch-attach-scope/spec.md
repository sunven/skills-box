# 批量挂载的全局与项目目标

Status: Implemented (2026-11-04)
Implementation: complete
Verification: [verification.md](verification.md)

## 原始需求

2026-11-04：用户以「批量挂载到 Agent」弹窗截图为背景，提出「批量挂载可以是挂载到全局，还是挂载到项目，挂载到项目可以选择一个目录」，并通过 grill-with-docs 确认设计、记录领域术语和必要的架构决定。

## 已确认的需求

- 批量挂载需要支持全局和项目两种位置。
- 选择项目时需要能够选择目录。
- Q1：主要场景为从全局列表选择一批 Skill，指定项目目录，使它们在项目 Agent 中可用，并保留原来的全局 Skill。
- Q2：弹窗顶部增加「全局 / 项目」选择；一次操作只有一个目标 Scope，项目模式一次只有一个 Project root。预览和确认显示本次目标。
- Q3：复制挂载时全局 Skill 的当前内容，由项目独立管理；此后全局更新或卸载不影响项目副本。领域术语为 Copy to project，之后在项目内创建 Agent attachment。
- Q4：项目目标提供已有项目列表与「选择目录」按钮。新目录仅在最终确认时注册；取消不注册，已有目录复用已有 Project，主界面保持全局 Scope。
- Q5：本次只在全局列表的批量挂载中增加目标 Scope 选择。项目列表继续只对当前项目批量 Attach。
- Q6：目的项目已有同名 Skill 时，内容完全一致则复用并补齐缺少的 Agent attachment；内容不同则跳过并说明冲突。已有挂载跳过，不覆盖目的项目内容。
- Q7：项目模式允许不选择独立 Agent，仅创建项目 Canonical store 中的副本。共享 Agent 可直接读取该目录，弹窗说明其可见性；独立 Agent 另行勾选。项目副本本身是一个可执行目标。
- Q8：来源资格沿用现有 Attach：只处理有 Canonical store 内容的 Managed skill；允许复制当前本地改动，预览提示。Unmanaged、Copy-only 或内容不可读取的 Skill 跳过。
- Q9：复制成功后某个 Agent 挂载失败，保留项目副本与成功挂载，继续处理其他目标。结果分别显示复制与各 Agent 挂载，重试仅处理失败或未执行部分。复用项目同名内容时保留项目既有管理记录。
- Q10：全局列表打开弹窗默认全局；切换目标类型或 Project root 清空 Agent 勾选，重新预览。来源内容、目的内容或根目录变化要求重新确认；提交后固定目标，写前发现变化的 Skill 跳过。
- Q11：最终确认后新 Project 保留注册，即使全批失败或停止。完成后不自动跳转，结果提供「查看项目」；用户可另行 Forget。未提交时取消仍不注册。
- Q12：新项目副本继承来源关联，以实际复制内容作为项目起始版本和本地基线，独立检查更新。复制包含本地改动时，即使上游没有新提交，也可能提示与上游内容不同；恢复上游内容仍须手动预览和确认。
- Q13：目的项目已有同名、内容一致的 Unmanaged skill 保持未受管状态。复制目标因已有内容跳过；新增独立 Agent 挂载按原规则跳过并说明原因，不自动补安装记录。
- Q14：项目模式分别记录和计数每个 Skill 的 Copy to project 与每个 Skill × Agent 的 Attach。3 个新 Skill、2 个 Agent 为 3 个复制目标加 6 个挂载目标；0 Agent 仍为 3 个复制目标。逐 Skill 先复制后挂载；复制失败，其依赖挂载不执行，继续其他 Skill。无可执行目标时禁用提交。
- Q15：来源 Canonical store 中的 Skill 根目录为链接时复制其实际内容。技能内部仅保留复制后仍指向自身内容的有效相对链接；绝对、外部或断开的内部链接导致整个 Skill 跳过并说明原因。
- Q16：整批沿用既有后台任务、写入许可、停止、关闭与退出规则，并锁定应用内其他写操作及 Project Relocate / Forget。一个 Skill 仅在其全部本次可执行目标成功时取消勾选；失败、未执行或执行中新跳过的 Skill 保留勾选，预览已跳过的目标不阻止其他可执行目标成功后的取消勾选。

## 最终交互

1. 在全局已安装列表勾选 Skill，打开「批量挂载到 Agent」。目标选择默认「全局」，沿用原来的批量 Attach。
2. 切换为「项目」后，通过已有项目列表或「选择目录」指定一个 Project root；切换目标清空 Agent 勾选。项目未选定时提示选择项目，禁用提交。
3. 展示项目名称与完整根目录，说明「复制当前内容，项目独立管理」和共享 Agent 无需单独挂载。仅展示该项目 Scope 支持的 Agent，独立 Agent 可多选，默认不勾选。
4. 预览以 Skill 计选中数量，以复制目标和 Skill × Agent 挂载目标计可执行、跳过和进度数量。每个目标显示目的位置、动作和跳过原因；源内容有本地改动或改动状态未知时明确提示正在复制当前内容。
5. 新目录在预览中仅作为已校验的待选 Project root；取消不注册，也不写入技能内容或本地基线。最终确认重新校验目录，复用已注册的同一物理目录，或注册新 Project，但不激活它。
6. 一批作为一个后台 Mutation task 串行执行。每个 Skill 先复制到项目或复用相同内容，再按选择器顺序挂载独立 Agent；来源 Global Scope 只读，目的只有一个 Project Scope。
7. 结果分别显示复制和挂载的成功、失败、跳过、未执行。成功部分保留；重试需重新预览和确认，只作用于失败与未执行部分。
8. 任务结束后主界面仍为全局；结果提供「查看项目」，由用户主动切换。结果保留至关闭，选择按 Q16 收尾。

## 内容与管理规则

- Copy to project 复制当前本地完整技能内容，不重新从上游安装，不让项目附件指向全局目录。
- 复制需要内容可读取、有效且可独立使用；路径与根目录沿用现有 Project 校验及物理包含规则。技能内部链接遵守 Q15。
- 同名一致性覆盖完整可复制内容，不能只比较入口文件或忽略本地改动的指纹。目的已有同名目录、链接或安装记录时核对实际内容和管理状态；不同、缺失、断链或无法核对的状态不覆盖，显示具体冲突原因。
- 新副本创建目的 Scope 的受管记录，继承原记录中已知的来源、源路径与 ref。项目版本值由实际复制内容产生，不能原样把全局版本指纹当作项目版本指纹，也不能声称复制时的本地改动是已发布的上游版本。
- 项目本地基线以本次成功复制的内容建立；此后项目内改动独立判断。复制时的全局本地改动是项目起始内容，相关提醒与 Q12 的上游差异提示需清楚表达。
- 当前项目版本算法无法可靠排序非 ASCII 文件名时，仍复制可读取内容并保留来源及独立本地基线；预览说明项目更新检查将显示未知，不写入虚构的上游版本指纹。此限制沿用现有项目更新检查。
- 复用同名内容不重写项目安装记录或本地基线；Managed 目的可补齐挂载，Unmanaged 目的遵守 Q13。
- 对已存在的正确挂载显示跳过；目标断链或其他冲突不自动修复或覆盖，沿用现有 Agent attachment 资格与路径规则。

## 执行与失效

- 最终确认固定来源 Skill、目的 Project root、Agent 和执行清单，不能因刷新纳入新的 Skill。
- 未提交时检测到来源、目的或目录状态变化，更新清单并要求重新确认；执行中每次写入前再次核对已确认范围，变化项跳过且保留选择。
- 复制仅发布完整的技能内容及对应管理记录；失败不得把不完整副本宣称为成功。复制失败后的依赖挂载显示未执行及原因；预览时已拒绝的挂载仍显示跳过。
- 普通目标失败继续；备份失败或无法继续任务时停止后续，保留成功部分。复制成功后挂载失败不回滚复制。
- 「停止后续操作」等待当前目标完成，再将尚未执行的可执行目标标为未执行；运行中弹窗保持打开。退出沿用等待或停止后续并退出规则，不强制中断当前写入。
- 新 Project 在成功注册后保留，即使无成功目标；无可执行目标的预览不能提交，因此也不会因此注册新 Project。
- 3 个 Skill、2 个 Agent 的计数是 3 个 Skill、最多 9 个操作目标，不能显示成 9 个 Skill。每个目标的终态均可查看，复制成功不掩盖挂载失败。

## 验收场景

- 全局模式仍执行同 Scope Attach；项目列表仍只执行当前项目的批量 Attach。
- 全局选择 3 个 Skill，选择新的项目目录和 2 个独立 Agent：预览 3 个复制加 6 个挂载；确认后项目内容独立存在，Agent 指向项目内容，全局内容保持原样。
- 同样选择 0 个独立 Agent：有 3 个复制目标，可提交，共享 Agent 从项目目录读取内容。
- 选择新目录后取消：项目列表、技能文件、安装记录和本地基线均不新增；选择已有项目目录复用其身份。
- 同名 Managed 目的内容一致：复制跳过，仅补缺失挂载，已有管理记录与基线不变。内容不同：该 Skill 的复制和依赖挂载跳过，不覆盖。
- 同名 Unmanaged 目的内容一致：保持未受管，已有内容与不能新增的独立挂载均说明跳过原因。
- 来源 Managed 且有本地改动：复制当前内容并提示；新项目受管、来源可追溯，后续独立检查更新。来源 Unmanaged、Copy-only、不可读取或链接规则不满足：跳过。
- 全局更新或卸载后，项目副本及项目 Agent attachment 不受影响。项目修改、更新或卸载也不改变全局 Skill。
- 某个 Skill 复制成功、一个 Agent 挂载失败：保留副本及其他成功挂载，只重试失败部分；复制失败时其依赖挂载未执行。
- 切换目的目录清空 Agent 勾选并重做预览；来源内容、项目内容或根目录改变后重新确认或执行时跳过，不扩大授权范围。
- 停止、退出、全批失败、注册保留、结果保留与选择收尾符合 Q9–Q11、Q14、Q16；无可执行目标禁用确认。

## 现状与设计约束

- 全局和项目已安装列表都支持同 Scope 的批量 Attach。当前弹窗沿用来源列表的 Scope，不提供单独的目标位置选择。
- 当前 Attach 从该 Scope 的 Canonical store 创建 Agent attachment；全局 Skill 的标识不能直接传给项目 Scope 的批量计划。
- [ADR-0011](../../docs/adr/0011-project-scope-registry.md) 规定每个 Scope 独立拥有 Canonical store、Lock entry、挂载和更新状态，Project 必须注册。
- [ADR-0021](../../docs/adr/0021-batch-operation-lifecycle.md) 规定一批操作持有一个 Scope 和一个后台 Mutation task；若要跨 Scope，需要明确内容与任务边界，不能仅替换目录。
- 现有添加项目流程会激活新项目；主界面随之清空选择并关闭尚未提交的批量预览。弹窗内选项目时必须明确与主界面 Scope 切换的关系。
