## 已确认决策

1. **项目选择（Q1）**：在截图红框处提供与技能页一致的「全局 / 项目」选择器，共用项目列表及当前选择。例如技能页选中项目 A 后进入插件页仍选中 A；插件页新增项目也出现在技能页。
2. **插件操作范围（Q2）**：项目支持覆盖插件浏览、安装、启用/禁用、更新或重新安装、卸载；每项按 Codex、Claude Code 各自真实能力提供。
3. **继承展示（Q3）**：项目视图同时展示本项目安装或配置的插件及继承的全局插件，标明安装来源与项目覆盖状态。项目内启用/禁用只写选定项目配置层；卸载全局安装需切换全局。不可确认的生效状态显示未知，不承诺改变已运行的宿主会话。
4. **项目配置层（Q4）**：Claude Code 同时支持「项目共享」和「仅自己在此项目」，默认项目共享，每次操作清楚显示写入哪一层。共享配置可随仓库提交，不表示协作者已经完成本机安装。Codex 按实际能力呈现，不虚构同等层级。
5. **项目市场管理（Q5）**：项目页同时管理插件市场：浏览来源，按宿主能力添加或移除当前项目配置层的市场声明，区分继承来源。配置层与原生安装的边界见 [ADR-0040](../../docs/adr/0040-native-plugin-project-context.md)。
6. **共享内容变化（Q6）**：项目内的市场同步、插件更新或重新安装，如果会改变全局或其他项目共用的内容，在能够确定影响范围、明确列出受影响对象并由用户确认后允许执行。影响无法确定则禁用；共享内容变化不等于允许改写其他层的启用配置或删除其他层的安装。
7. **跨范围删除（Q7）**：卸载插件或移除市场仅允许删除所选项目与配置层内的目标；若原生命令会连带删除全局、其他项目或当前项目另一层的安装/声明，应用内阻止该操作，并说明受影响对象及需在宿主处理。仅移除当前层市场声明且能保留其他层安装时允许；无法判定影响时继续阻止。
8. **Codex 能力限制（Q8）**：维持官方接口原则。当前 Codex 项目页提供可确认的项目读取和来源/覆盖展示，项目启停及项目市场声明写入显示不可用及具体原因；其他操作须满足官方能力与 Q6、Q7 的影响边界，经独立验证后开放。保留全局入口供用户显式切换，不把项目操作静默改成全局操作，不承诺当前版本完整项目写入。
9. **重新定位（Q9）**：保留应用项目身份并从新根重新读取原生状态，不自动迁移插件内容或改写宿主原生安装记录中的旧项目路径。若记录仍指向旧路径，说明需在宿主修复或重新安装；不能把旧根安装当作新根安装，也不能静默切到全局执行。

## 实现前的仓库事实

- `src/App.tsx` 在插件页把 `scopeSwitcher` 设为 `null`，没有向 `NativePluginsPage` 传递项目。
- `src/lib/native-plugins.ts` 的插件请求没有作用域或项目字段，读取缓存仅区分宿主。
- 后端插件命令的工作目录固定为 `/`，Claude 插件写操作固定 `--scope user`，Codex 启停写入用户配置。
- 现有项目注册表提供稳定项目身份、根目录、最近使用排序、重新定位和遗忘；技能页已有对应选择器和对话框。
- 现有选择器包含技能路径提示、技能更新和锁文件状态；复用时需要按插件语义处理。
- 当前跨作用域保护会阻止部分影响项目安装的插件或市场动作。这些保护反映现有用户级管理边界，不代表宿主没有项目能力。

上述为仓库实现事实。宿主当前项目能力见[官方文档与仓库证据核查](research/01-scope-capabilities.md)，不将实现中的限制当作原生能力结论。

## Codex 隔离验证结果

2026-11-20 使用本机 Codex 0.170.0、独立配置目录及临时可信项目完成[最小接口核查](research/02-codex-project-write-probe.md)：

- 官方 `config/read` 可读取项目层配置和版本。
- `config/value/write`、`config/batchWrite` 在项目路径、信任和版本均正确时返回 `configLayerReadonly`，明确只允许写用户配置。
- 项目 cwd 的市场添加仍写用户配置，不能作为项目市场添加；移除项目独有市场声明被原生接口拒绝。
- 没有发现可用的项目启用覆盖清除接口。插件安装、重装、卸载及市场同步未在这次最小核查中执行，不能将其标为已通过项目验收。

此结果不建立版本白名单。Q8 已确认接受这个具体能力限制，继续遵循官方接口边界。原型或临时 fixture 文件的创建不是直接编辑用户配置的产品兜底。

## 启用状态与恢复继承

「继承」「显式启用」「显式禁用」属于不同配置状态。启用一个原先禁用的项目插件会形成显式启用，不代表清除该层覆盖。Codex 0.170.0 的项目配置写入被原生接口拒绝；Claude Code 2.1.325 的本机帮助和当前查阅官方文档也未发现单独清除启用覆盖的可靠接口，详见[核查 03](research/03-inheritance-and-project-lifecycle.md)。据 Q8 及原有官方接口原则，首版不提供未获支持的独立「恢复继承」写操作，明确当前覆盖来源并提示用户外部调整后重新读取；不以卸载、重装、写入与继承值相同的值或直接编辑配置冒充恢复继承。

## 延续的约束

- 沿用原生 Plugin 状态所有权、官方接口、按能力提供操作、异常结果禁用受影响动作和写后核验原则；不新增精确版本白名单，不以直接编辑配置兜底。
- 插件操作仍为单项手动操作，沿用现有确认、互斥、退出等待和异常中断后的状态核对；不扩展自动更新、批量管理或完整插件备份。
- 项目注册、重新定位和遗忘沿用既有语义及 Q9。项目选择不是迁移安装；遗忘不删除文件、插件或宿主配置。

## 行为与验收条件

以下由 Q1–Q9 和既有约束细化，已纳入用户最终整体确认。

1. **入口与项目身份**：技能页和插件页共用项目列表及当前选择；添加项目可从任一页使用。插件页显示宿主、全局或项目、当前项目路径及原生配置层，避免技能路径、技能更新徽章或技能锁错误被误用为插件状态。
2. **安装与配置区别**：同一原生插件在用户、项目共享、项目个人层的安装和启用设置分别保留。列表可展示同一插件的继承与覆盖关系，不因显示名相同合并不同宿主/市场插件，也不把继承项误标为本项目安装。
3. **覆盖与实际状态**：操作成功表示所选层设置已被核对；如果被另一层或策略覆盖，展示覆盖来源，不宣称宿主的实际启用状态已经改变。未知状态、未安装、未配置和读取失败分别显示，不承诺改变现有会话。缺少恢复继承接口时如实说明，不把显式启用伪装成继承。
4. **原生能力差异**：用临时配置和临时项目验证目标宿主。Codex 项目配置写入的已知拒绝与 Claude 的 project/local 能力分别呈现；不依赖精确版本白名单，不把 cwd 误当项目写入保证，不静默改成用户级操作。
5. **共享内容与删除**：创建全局、项目 A、项目 B、A 的个人层安装与市场声明。同步/更新覆盖 Q6 的确认及未知影响禁用；卸载/移除覆盖 Q7 的跨层阻止、唯一声明移除和其他项目仍有声明等情形。用户未在应用注册的项目若出现在原生记录中，也不能从影响核查中排除。
6. **确认目标与外部变化**：确认明确宿主、原生配置根、项目身份与根路径、配置层、原生对象身份及影响范围。切换项目、重新定位、遗忘、CLI/配置根变化或外部原生状态变化后，旧确认不能写到新目标；执行前重核事实，变化则刷新确认。
7. **生命周期与刷新**：原生操作从执行到核验持有公共互斥，项目重新定位/遗忘不能改变进行中操作的根；正常退出等待核验结束。写后按实际影响刷新所有相关全局/项目视图，不只刷新当时可见列表；旧请求不能覆盖新的项目状态。
8. **失败与项目不可用**：保留明确的加载错误和需要核对的结果；项目目录不可用时不回退到全局写入。重新定位后重读新根、使旧确认失效，旧路径安装不能误归属于新根。忘记项目不卸载原生插件，也不因此忽略原生记录中的跨范围影响。部分写入、认证/信任阻断和写后核验失败沿用现有结果语义，不能自动重复写入。
9. **验证范围**：覆盖 App 页面选择与目标切换、按作用域的请求/缓存、后端目标约束、两宿主隔离原生操作和相关既有技能/全局插件回归。未知能力、失败能力和通过能力分别记录，不将按钮禁用冒充操作验收通过。
