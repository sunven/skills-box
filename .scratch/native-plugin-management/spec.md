# Codex 与 Claude Code 原生插件市场管理

Status: implemented with host capabilities and observed-state limits; acceptance recorded in implementation.md.

日期：2026-11-19。设计访谈 Q1–Q19 及整体规格均已由用户确认，包括下文的具体行为、继承约束与验收条件。访谈结束，没有未回答的产品分支；2026-11-20 已实现独立插件管理与原生操作适配，并完成隔离原生验收；通过项、禁用能力和已有环境测试失败见 [实现与验收记录](implementation.md)。2026-11-20 用户进一步确认移除精确版本白名单，保留基本兼容性检查、作用域检查及写后核对，以下兼容策略以此决定为准。

## 已确认决策

1. **管理对象（Q1）**：管理 Codex 与 Claude Code 各自原生支持的 Plugin。Plugin 是完整管理单元，与 Skill、Expert pack 区分；包含多个 Skills 的 Plugin 仍保留插件身份。
2. **项目与参考关系（Q2）**：在 Skills Box 内新增能力。`/Users/sunven/github/package-manager` 是功能与实现参考；页面沿用 Skills Box 的结构，实际能力以核查结果为准，不要求完整迁移参考项目。
3. **首版操作范围（Q3）**：涵盖市场添加、刷新、移除，以及插件浏览、搜索、详情、安装、启停、卸载和更新类操作。“更新”与“重新安装”按各宿主实际行为区分。
4. **作用域（Q4）**：首版管理用户级插件和市场，项目级管理留待后续。项目配置可能影响插件实际生效状态，界面应准确说明。
5. **状态归属（Q5）**：以 Codex、Claude Code 自己的安装记录和配置为准，纳入用户此前通过 CLI 或官方界面安装的插件。Skills Box 管理原生状态，插件安装记录继续由宿主拥有；不另建竞争性的安装记录。见 [ADR-0037](../../docs/adr/0037-native-plugin-state-ownership.md)。
6. **入口布局（Q6）**：新增独立「插件」入口，在其中切换 Codex / Claude Code，与现有「技能市场」并列。
7. **市场来源（Q7）**：读取两端已经配置的市场，支持手动添加市场地址或本地来源；浏览和搜索限定在这些市场中。首版不增加公共市场推荐榜或额外聚合目录。
8. **组件与认证边界（Q8）**：以完整插件为操作单位。插件内 Skills、Hooks、MCP 等只展示组成信息；组件编辑以及登录、授权、信任确认交给 Codex / Claude Code。
9. **详情内容（Q9）**：展示目录提供的介绍，并读取本地已有的插件说明和组件清单。尚未下载的内容明确显示不可用，不为详情额外下载整个远程插件。
10. **执行方式（Q10）**：优先调用官方 CLI；Codex 启停使用官方配置写入接口。无法可靠执行时明确禁用该操作，不自动退回直接修改原生配置文件。
11. **版本兼容（Q11，2026-11-20 修订）**：按宿主提供适配器已实现的操作和市场来源格式，不以精确版本名单或最低版本放行。版本保留用于展示、异常检测缓存和操作确认指纹。实际响应或写后状态不符合预期时只停用受影响操作；可选基本兼容性检查只更新实际覆盖的动作，保留同步、移除市场及来源格式的现有状态，不宣称跨版本自动兼容。
12. **读取与同步（Q12）**：「重新读取状态」与「同步市场」分开。同步属于写操作，执行前说明可能影响该市场已配置的插件文件，包括禁用插件；普通页面刷新只重新读取。
13. **Codex 重新安装（Q13）**：按经过验证的原生行为执行，使用「重新安装」名称。如果会启用原先禁用的插件，确认时明确提醒；不承诺取得最新版或保留禁用状态。
14. **移除市场（Q14）**：先核对连带影响，仅在能确定影响属于用户级时允许移除，确认页列出受影响插件及数据后果。检测到项目级安装或影响不明时阻止，交给宿主处理；不能仅凭 `--scope user` 放行。执行及副作用边界见 [ADR-0038](../../docs/adr/0038-native-plugin-execution-boundary.md)。
15. **单项操作（Q15）**：首版采用「选择一个插件或市场 → 确认 → 执行 → 重读结果」的手动流程，不增加批量操作或 Skills Box 自动更新插件；宿主已有的自动更新设置保持原样。
16. **来源格式（Q16）**：支持各宿主经过验证的原生格式，包括 Git 仓库、本地目录及 Claude Code 的市场 JSON 文件/URL；分支与 sparse 等选项按宿主能力提供。私有来源使用已有本机凭据，不新增独立账号或凭据管理。
17. **验收标准（Q17）**：在隔离配置目录和临时项目中真实验证两端的安装、启停、更新或重新安装、卸载、市场同步及移除，覆盖跨作用域、外部配置变化、部分失败及批准需求。未验证通过的操作明确不可用，不能因此宣称该项完整交付。
18. **失败与恢复（Q18）**：原生命令可能部分写入后失败。保留实际结果，重读并展示已完成、失败或未知状态；重试前重新核对目标，必要时在宿主中恢复。首版不提供完整插件备份或自动回滚。
19. **写入期间退出（Q19）**：写入开始前可以取消；开始后等待当前操作及状态核验结束，再正常退出。应用内不提供强制中断插件写入；系统强制结束或异常中断后标记待核对。恢复与任务协议见 [ADR-0039](../../docs/adr/0039-native-plugin-operation-lifecycle.md)。

## 事实基础

详见 [初步事实调查](research/01-existing-implementations.md)。调查结果不是用户已接受的产品决策。

- Skills Box 已有 SkillHub、skills.sh、ClawHub 技能市场和 SkillHub 专家包；原生 Plugin 管理是新增领域能力。
- 参考项目已实现两端的插件与市场管理，写入集中在用户配置；Codex 的重新安装与 Claude Code 的插件更新具有不同语义。
- 本机 `codex-cli 0.170.0` 与 `Claude Code 2.1.323` 都提供插件/市场 CLI；命令、启停与作用域能力不对称。
- 参考项目把 Claude Code 写入限制为 `2.1.300`。Q11 已决定不照搬精确版本锁；原生行为仍在隔离环境中验收，但运行时不以已测试版本名单放行。
- [执行与作用域核查](research/02-execution-and-scope-boundaries.md) 补充了官方配置接口、市场同步副作用、跨作用域移除和当前版本仍需隔离验证的行为。Codex 直接编辑 TOML 是参考项目选择，不是唯一可行路径。
- [任务生命周期核查](research/03-operation-lifecycle-integration.md) 明确可复用公共任务、互斥与更新保护，但现有 Skill 快照、安装记录和强制退出语义不能直接套到 Plugin。

## 页面、范围与身份

入口为「插件 → Codex / Claude Code」。页面明确标注当前宿主及用户级范围，Skills Box 的技能项目选择不改变插件操作目标。两端分别读取原生工具使用的配置根，遵循其现有环境配置；首版不新增多配置档案管理。配置根或 CLI 发生变化时，重新检测能力和读取清单，旧操作确认失效。

- 展示已配置市场及其中的插件，提供名称/简介搜索与全部、已安装、未安装筛选。搜索范围明确属于已读取的市场目录，不宣传为公共插件总目录；来源读取不完整时不能呈现为完整搜索结果。
- 市场和插件是不同对象。空市场可管理；已安装但当前市场不可读或不存在的插件仍可展示，不因目录缺失伪装成未安装。
- 插件身份保留宿主、配置根、原生插件标识及市场归属；作用域属于安装身份。相同显示名不合并，不跨宿主安装或同步。已存在的市场名称/来源冲突按原生规则报告，不静默覆盖或自动改名。
- 已安装、用户启用设置、实际生效状态分别显示。用户默认值不等于当前项目或既有会话中的实际效果；不能确认时显示未知/未设置，并说明需在宿主的新会话中核对。
- 组织、系统、项目或其他配置层提供的对象可以作为只读信息展示；只有确认归属与影响均符合用户级范围的操作才可执行。需要读取其他作用域来检查移除影响，不等于提供项目管理。

## 来源与详情

添加市场时按宿主显示适配器支持的来源格式与可选参数：Codex 为本地、Git，Claude Code 为本地、Git、JSON 地址；不因 CLI 版本变化缩减选项。使用选定宿主的原生命令验证并注册市场，不把已有 Skill Marketplace source 或 Git Source 记录改造成原生市场记录。

详情展示可取得的名称、市场、来源、介绍、版本信息和本地说明，以及 Skills、Agents、Hooks、MCP 等组件声明。缺失字段保持缺失；没有本地内容时明确说明。组件声明不代表其已经加载、连接或取得授权，详情不执行插件内容。

目录加载可以使用原生工具的正常目录/缓存读取能力，不能因此承诺完全离线；也不能为实现普通刷新而调用会安装、更新插件或修改市场配置的命令。若某读取命令存在这种副作用，须改用经过验证的只读路径或把该能力标为不可用。

## 操作契约

| 操作 | 行为与确认内容 |
| --- | --- |
| 重新读取 | 获取宿主原生状态与可用目录，不调用插件/市场变更命令；读取失败与空列表区分 |
| 添加市场 | 确认宿主、用户级范围、来源与参数，通过原生工具添加后重新读取 |
| 同步市场 | 明确是写操作，只请求所选市场；说明宿主可能同时刷新或安装该市场已配置插件，含禁用插件 |
| 安装 | 只请求所选原生插件；宿主的依赖或连带动作按已验证契约说明，不将附带安装伪装成额外用户选择 |
| 启用/禁用 | 修改用户级设置，区分用户默认值与生效状态；Codex 官方配置接口需通过插件开关路径验证 |
| Claude Code 更新 | 使用原生插件更新能力；读取并核对原生版本/引用和启用设置，不套用 Skill 的版本比较或内容基线 |
| Codex 重新安装 | 使用原生重新安装行为；可能启用时提前说明，不承诺升级或保留禁用状态 |
| 卸载插件 | 确认所选插件、宿主、用户级范围及原生数据影响；不自行追加删除原始来源、共享缓存或凭据 |
| 移除市场 | 检查全部可观测安装作用域及配置归属，列出连带插件与数据影响；存在非用户安装或影响不可判定时阻止 |

一个“单项”请求不等于原生工具只改一个目录：市场同步、依赖处理及移除均可能有连带影响。若实际影响不符合已经确认的范围，阻止操作并说明原因。安装预览确认原生目标与动作，不承诺未经原生接口保证的远程内容不可变性。

所有写操作先形成可审阅确认，显示宿主、目标、用户范围、来源、实际命令或配置动作及适用的连带后果；敏感凭据值不出现在展示中。执行前重新检查配置根、CLI 能力、对象身份、来源、归属及确认所依赖的状态。发生变化就刷新预览并要求重新确认，不对过期目标执行。

写后同时记录命令执行结果和原生状态核对结果，不能仅凭退出码报告成功；也不能因为列表重读失败就自动重跑写命令。重试是重新核对后的新操作。CLI 请求被批准/认证要求阻断时，显示需要在宿主处理，用户处理后重新读取；不自动接受命令、不代管登录，也不将其标为成功。

## 兼容、失败与结果

| 情况 | 预期行为 |
| --- | --- |
| 一个宿主 CLI 缺失或不可调用 | 该宿主显示依赖状态与重新检测；不影响另一宿主或既有 Skill 管理 |
| 命令执行失败、结构未知或实际副作用不符合预期 | 显示具体失败；响应或写后状态不符合预期时只停用受影响动作，不回退为直接写配置 |
| 一个市场读取失败 | 保留其上次成功内容时明确标注旧数据；独立展示错误和重试，不清空其他市场 |
| 外部 CLI/官方界面修改状态 | 重新读取后反映原生状态；任何写前发现的变化使旧确认失效 |
| 原生命令失败但已有变更 | 显示失败或部分完成以及能核对的当前状态，不宣称所有变更均撤销 |
| 命令结束但核验失败 | 标记结果待核对，提供重新读取；不报已成功，也不自动重复写入 |
| 非用户配置覆盖或影响范围不明 | 不写入非用户配置；无法确定用户级目标或影响时阻止操作。若用户设置已保存但被高层覆盖，如实报告覆盖，不宣称实际启用状态已改变 |
| 需要安装命令批准、认证或信任 | 引导到宿主完成后重读；不静默批准或循环重试 |
| 应用或系统异常中断 | 保留插件操作的身份和中断记录，下次重新读取并说明可确认结果与剩余未知 |

Q11 不再以特定 CLI 构建是否有验证记录作为默认操作门槛，也不以版本号较新宣称行为已经兼容。默认能力受配置归属、安装作用域、来源限制和清单完整性约束；执行结果仍核对响应及原生状态。可选基本兼容性检查不能覆盖同步或连带移除的异常禁用记录，也不能缩减或扩展市场来源格式。开发验收记录只描述实际测试过的版本和场景。

## 任务、退出与恢复

Plugin 和 Plugin marketplace 写操作接入应用既有 mutation permit、运行中任务与退出/更新协调，由实际执行 worker 持有到写入及核验结束。App update 下载可继续；应用更新安装与重启必须等待写操作结束。切换页面或丢弃 IPC 请求不能提前释放操作所有权。

公共进度、错误、结果和刷新界面可以复用，但插件目标、核验、刷新键和中断记录独立于 Skill 的 ScopeLayout、锁文件、Canonical store、Agent attachment 与 Backup snapshot。原生记录是唯一安装事实来源；操作记录只描述进行中/已结束的动作，不形成第二套安装账本。

写入前取消不执行原生命令。写入开始后封闭普通取消窗口，正常关闭/退出等待该操作和核验结束；不得借用现有 Skill 单任务的强制退出路径杀死插件写入。原生命令异常终止或协议失联应呈现失败/待核对，不能声称未发生写入；仍在写入的进程不得因前端请求超时而失去所有权。

首版不新增完整 Plugin 备份或一键回滚。保留可观测实际结果与必要诊断，通过重新读取和宿主处理恢复；不把 Skill 的「恢复技能」或快照目录当成完整插件恢复能力。既有 Skill 备份、取消、退出和更新语义不因本功能改变。

## 实现前验证与验收

开发验收使用隔离配置和临时项目验证原生接口，运行时不以测试过的版本名单启用能力。需要真实验证的前提不足时，记录受阻原因，不改成在真实用户安装中试验。

1. **原生接口**：覆盖当前 Codex/Claude 插件和市场读写命令、返回结构及退出码；验证 Codex `config/value/write` 对插件身份转义、缺省值、版本冲突和覆盖结果的行为。失败时该操作不可用，不能私自改成直接文件写入。
2. **安装身份**：通过宿主直接安装的插件可正确识别；同名不同市场、不同宿主及不同作用域不合并。市场不可读、缺失或目录为空时，保留独立安装状态。
3. **生命周期**：两端真实完成添加市场、安装、启停、更新/重新安装、卸载和移除；核对记录、内容与启用状态，不仅检查命令退出成功。
4. **同步与重装副作用**：验证 Codex 同步对禁用插件和已配置插件的内容影响、重新安装后的启用状态，以及市场移除对实际安装/缓存的后果；普通重新读取不得触发这些变更。
5. **作用域与归属**：覆盖 Claude user/project/local 同市场安装与多处声明，验证移除的确切范围；测试非用户配置覆盖、归属缺失和不可判定影响的阻止行为。
6. **失败及并发**：覆盖未知结构、网络失败、缺依赖、需要批准、原生部分写入、执行后核验失败、外部变更和旧确认；失败不能自动重跑或被包装成成功。正常退出等待写入与核验，异常中断后能重新核对；App update 安装与原生写入互斥。
7. **页面流程**：验证独立插件入口、宿主切换、用户级标识、市场与安装状态分离、搜索/筛选、本地详情缺失状态及需要外部操作的提示；技能项目切换不能改变插件操作目标。
8. **回归**：保持 Git/SkillHub/skills.sh/ClawHub、Expert pack、Skill 安装/更新/挂载/卸载、应用数据与 App update 原有行为。执行适当的前端测试、生产构建和 Rust 测试，并记录已有环境限制。

验收记录逐项区分通过、失败和受阻，包含工具版本及隔离方式；测试数据、安装与删除操作均不得触碰真实用户插件。单项能力被禁用不等于该能力已经通过验收。
