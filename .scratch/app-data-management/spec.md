# 设置中的应用数据管理

Status: ready-for-agent
Implementation: complete

日期：2026-11-09。Q1–Q13 已由用户确认；用户随后要求「开始实现」「继续」。下文记录最终实现范围，验证见 [verification.md](verification.md)。

## 目标与入口

在「设置 → 应用数据」管理 Skills Box 自身产生的数据。顶部展示总占用、可清理占用、应用数据目录与上次统计时间，并提供刷新入口；下方展示操作备份、诊断日志、缓存、需保留的数据与集中清理。

## 数据边界与统计

默认根目录为 `~/Library/Application Support/com.sunven.skills-box`。统计使用文件的逻辑大小，不代表文件系统实际分配的磁盘块；目录元数据不计入。不跟随符号链接，不扫描或清理已安装 Skill 文件、Agent attachments、npm 等外部工具缓存或 WebView 浏览器整体数据。

| 类别 | 内容 | 清理规则 |
| --- | --- | --- |
| 操作备份 | `backups/` 中的 Global 快照及 `backups/project-<id>/` 中的 Project 快照 | 可删除未被引用且信息完整的快照 |
| 诊断日志 | `logs/operations.jsonl` 与 `operations.1.jsonl` 至 `operations.4.jsonl` | 用户预览确认后删除 |
| 缓存 | `cache/update-tree-*.json` 与 `cache/archives/` 中的 Source archives | 用户预览确认后删除；需要时重新获取 |
| 需保留的数据 | 设置、额外 Agent 配置、项目登记、发现历史、更新检查结果、本地修改基线、运行协调状态与 CLI 工作目录 | 只统计，不可勾选 |
| 其他文件 | 根目录与已知分类目录内未识别的文件 | 单独展示占用，只统计 |

总占用包括能成功统计的上述分类；可清理占用排除受保护、未知和无法完整统计的项。读取失败时提示统计可能不完整，不用零值冒充完整结果。顶层符号链接只计链接自身大小并提示，不参与清理；删除目录时不跟随内部链接。

## 操作备份

备份指已有的操作前 Backup snapshot，例如卸载前保存的技能内容、挂载信息和 Lock 数据，不是整套应用数据导出。适用于现有会生成快照的安装、更新、卸载、移除挂载、清理记录和恢复等流程。

「保留操作备份」默认开启。关闭后仍按原协议先备份再修改文件，成功并完成验证后删除本次成功目标对应的快照。失败、中断或单次操作取消时保留；批量操作停止后，已独立成功的目标可删除自己的快照。与失败目标共享的快照继续保留；任务级安装快照仅在整次操作成功后删除。开关以操作开始时的值为准，切换不删除任何旧快照，也不推断旧快照的操作结果。见 [ADR-0028](../../docs/adr/0028-backup-retention-after-success.md)。

备份列表按新到旧展示时间、操作、技能或任务名称、Scope/项目及大小，支持打开备份目录、打开单个快照目录、删除所选与清空可删除备份。「全选可删除备份」可全选或取消全选，显示部分选中状态，自动排除受保护项；没有可删除备份时禁用。安装任务级快照明确标为安装任务；已移除项目使用项目标识作为回退。首期不提供快照恢复、整套导出、按时间或数量自动淘汰。

运行中或中断 Mutation session 引用的快照标为「受保护」，不能勾选。中断记录损坏时保护全部备份；快照信息不完整时计入占用并保护，允许打开目录检查。失败操作的快照在引用清除后可以手动删除。

快照必须是实际目录。备份根目录或项目备份目录内的 `.DS_Store`、备注文件等普通文件计入「其他文件」，不进入备份列表，也不提供打开快照或删除操作。信息不完整的真实快照目录仍按受保护备份处理。

## 诊断日志

「记录诊断日志」默认开启。关闭后，之后开始的操作不再追加现有日志；已经开始的操作按开始时的值完成写入。已有日志保留到用户清空或启用日志时触发轮转。

日志仍是部分技能操作的结果与错误记录，不扩展为完整运行日志或长期操作历史；不持久化第二套 CLI 调用历史，遵循 ADR-0026。提供大小展示、打开目录和清空功能。

每个日志文件最多 10 MiB，共保留 5 份（含当前文件），合计最多 50 MiB。新记录将超过当前文件上限时轮转，淘汰最旧文件。升级前已经超限的 `operations.jsonl` 在下一次写入触发轮转时只保留尾部能容纳的完整记录；仅切换开关不会裁剪旧文件。日志写入失败不会把已经成功的技能操作变成失败。

## 清理流程

1. 分类入口可清理日志、缓存、所选备份或全部可删除备份。集中清理默认只勾选缓存，备份与日志需要手动勾选。
2. 后端扫描选定项，生成带具体项目列表及预计释放空间的预览。弹窗说明各类别删除后果，默认焦点落在「取消」；取消不删除文件。
3. 用户点击「确认清理」后执行。技能写操作、发现扫描或更新检查正在使用数据时提示稍后重试，不自动排队；应用安装更新期间也禁止清理。
4. 预览只允许执行一次，10 分钟后失效。删除前重新检查已确认项的路径、文件身份、大小、修改时间及保护状态；任何已确认项变化则要求重新预览。预览后新产生的独立文件不自动加入删除范围。
5. 单项删除失败时继续处理其他已确认项，显示实际释放的逻辑字节数与每项失败原因。重试只重新预览失败项，并再次要求确认。
6. 完成后刷新占用与备份列表。数据统计、扫描和删除在阻塞工作线程执行；即使 IPC 调用者离开，删除期间仍持有写操作与缓存协调保护。

「重新预览清理」仅随清理预览或执行失败显示，使用该次失败对应的选择。打开目录、保存偏好或读取数据失败不沿用之前的清理重试入口；重新打开目录时清除上一次打开错误。

前端只提交类别、服务端生成的项目标识或预览标识，不传任意待删除路径。后端限定到应用数据目录，拒绝路径穿越和分类目录被替换为符号链接的情况。不会对外部 CLI 进程或用户直接修改文件提供事务保证。

## 设置兼容

已有 version 1 的 `settings.json` 缺少新字段时，两项开关均默认开启。保存数据偏好不会清除 GitHub token 或未知配置字段；保存或清除 token 也不会重置数据偏好。继续使用原子替换与 Unix `0600` 权限，不向应用数据接口返回凭据。

## 验收

- 进入独立页签能查看占用分类、目录、时间及统计错误；刷新更新当前值。
- 两项开关持久化，保存失败保留原值；操作开始后修改开关不改变该次策略。
- 卸载先生成快照，关闭保留后只删除成功操作的新快照，失败、受保护及旧快照仍在。
- 列表和清理预览排除受保护快照，伪造标识或变化的路径不能绕过删除边界。
- 集中清理默认只选缓存，取消不删除；清理后设置、项目登记、发现历史、检查结果、基线和用户技能仍在。
- 忙碌、预览失效、部分失败均给出可理解反馈，重试仍需新的确认。
- 现有凭据、Mutation session、批量操作、更新检查及发现功能通过回归测试。
